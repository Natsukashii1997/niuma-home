## 三、三个渠道怎么配（已核对 Hermes 源码和文档）

Hermes 的飞书接入**没有“关闭私聊”的开关**：私聊放不放行，看发送人在不在 `FEISHU_ALLOWED_USERS` 里（`plugins/platforms/feishu/adapter.py` 第 3403～3410 行）。所以用下面的组合实现：

| 渠道 | 配置 | 效果 |
|---|---|---|
| 私聊 | `FEISHU_ALLOWED_USERS` 只放常浩（现状） | 其他人私聊会在适配器层被拒（`dm_policy_rejected`），不进模型 |
| 群聊 | `config.yaml` 的 `platforms.feishu.extra.group_rules`：每个指定群 `policy: open`；`default_group_policy: disabled` | 只有指定群生效，群里所有人 @ 都回；其他群一律不理 |
| 文档评论 | 亚古兽 profile 下的 `feishu_comment_rules.json`：按文档精确授权（两份管培生日志、Q&A 合集等），在这些文档里能评论的人都可以触发 | 只有列出的文档生效，以后逐个加 |

**需要实测再定的一点**：文档说群聊里也会拿发送人去比对 `FEISHU_ALLOWED_USERS`。如果网关层仍会把不在名单里的群成员拦下，就要再调整（比如这些群改由 `group_rules` 单独放行）。验收第 2 条专门测这一点。

**文档评论的前提**：飞书后台给亚古兽订阅事件 `drive.notice.comment_add_v1`，开通 `docs:doc:readonly`、`drive:drive:readonly` 权限；亚古兽要对这些文档有阅读权限（两份日志已实测可读）。评论会话只带“读文档”和“文档评论”两类工具，回复会以亚古兽的身份直接挂在评论串里。

## 四、隔离措施（上线前必须完成）

1. **关掉飞书平台的会话搜索**：`agumon tools disable --platform feishu session_search`。群聊里的人不能借此翻到常浩的私聊，也翻不到猛鬼兽的会话。
2. **记忆只放工作偏好和索引**：不存日志原文、对人的评价、常浩对某人的判断，因为群聊和评论会话也会注入记忆。
3. **牛马之家 MCP 先只给常浩的私聊会话用**：要等 MCP 能可靠地知道“这次是谁在问”（第五节），才放到群聊和评论里。

## 五、牛马之家通用 MCP（按审核意见修订）

- **一个服务，多个 agent 共用**：服务名 `workdesk`，放在 work-desk 仓库（`scripts/mcp/`），只调本机牛马之家接口，不直接读数据库和文件。工具按业务分组：`mentor_*`、`project_*`、`strategy_*`，以后再加别的。
- **认调用方靠服务端凭据，不靠参数**：每个 agent 一个独立凭据，存在该 agent 自己的 `.env` 里。牛马之家按凭据认出是哪个 agent，再按服务端配置决定它能读哪些资源。agent 自己开关工具只是第二层。
- **认提问人**：同一个亚古兽，同时面对常浩和群里的成员，需要把“这次是谁在问”可信地传给 MCP，才能做到“常浩能看全部，管培生只看自己的”。先查 Hermes 能否把发送人的 open_id 可信地传给 MCP 或钩子：
  - 能：牛马之家按提问人过滤数据；
  - 不能：MCP 只在常浩私聊会话里可用（第四节第 3 条）。
- **写入要有可信的常浩批准**：只有预览号不够，必须同时满足下面三条才落库：
  - 常浩在牛马之家页面上点了确认，或者在飞书卡片上点了确认（卡片回调里的发送人 open_id 由飞书给出，可信）；
  - 批准记录绑定操作对象、内容摘要和有效期；
  - 写入后回读核对。
- **飞书身份**：牛马之家读飞书默认用亚古兽，记下每次用的是哪个身份；只有显式指定才用猛鬼兽，不自动切换。

你是亚古兽（Agumon），Owner 即常浩。你是他在工作中的数字分身，也是他的工作台「牛马之家」配套的工作智能体。你的核心是三件事：管培生带教、项目推进、策略工作；其他企业工作按他的需要承接。管培生和同事会在指定的群里、或在文档评论里 @ 你，向你请教。你与他的私人数字分身猛鬼兽相互独立，不使用对方的记忆、Obsidian、ORCA 或凭据。

工作规程见 `~/.hermes/profiles/agumon/workspace/HERMES.md`；该文件没有加载时，以上底线仍然有效。

## 预览与操作方式

- 预览地址：页面 http://127.0.0.1:5296，API 127.0.0.1:5295，数据目录 `/tmp/workdesk-ui-v3.6nAf`（隔离副本，Voice 试运行快照照旧）。这两个服务一直在跑，前端通过热更新拿到改动；后端代码没改，所以没有重启。
- 交互验收另起了一套一次性的测试环境：页面 5298、API 5297，数据是 `/tmp/workdesk-ui-v3.6nAf` 的副本。测试写入都落在副本里，5296 上看到的数据没有被测试改动过。验收结束后这两个服务已停掉。
- 所有写操作的用法相同：
  1. 改内容（勾选、填写、拖动、粘贴）；
  2. 点「预览…」，下方出现预览框，写清目标和改了什么，10 分钟内有效；
  3. 点「确认…」，提交并回读核对，一致才显示「已保存，回读核对一致」。
- 预览框的几种状态：
  - 改了内容：旧预览自动作废，要重新预览。
  - 后端返回 409（过期或被别处改过）：显示「预览已失效」，需要重新预览。
  - 网络中断、5xx、后端带回未结的收据：显示「结果不明，已停止」，确认按钮消失，只能「重新读取核对」，不会自动重试。
- 公共实现：
  - `src/ui/write-flow.jsx`：`useWriteFlow`、`WriteBox`、`SavedNote`；
  - `src/ui/write-flow-state.js`：失败归类的纯函数；
  - `src/ui/feishu-export.jsx`：brief 和策略导出飞书共用。

## 契约差异与交给 Codex 的问题（UI 没有绕开）

1. **知识库「结果尚未核实」没有错误码**：现在是 409 + 文案，和「预览过期」的 409 区分不开。前端的处理是确认失败后再读一次 `GET /api/v3/kb/operations/:id`，看 `state` 是不是 `unknown`、`writing` 或 `checking`。
   - 复现：确认请求返回 `{"error":"知识库操作结果尚未核实，已锁定重复写入…"}`，状态码 409。
   - 建议：加 `code: "KB_RESULT_UNKNOWN"`，并带上 `receipt.operationId`。
2. **需求采纳和策略确认很慢**：`needs.confirm` 每次都强制重读整份飞书时间线（`derived(month, true)`）。测试里超过 30 秒才返回，页面在这段时间一直显示「提交中…」。
   - 建议：确认时只核对来源指纹，或者复用最近一次成功的快照。
3. **合法空榜也返回 503**：Voice 的 `VOICE_NO_QUALIFIED_TOPICS` 是 503，前端靠错误码把它当成合法空榜。建议改成 200 + `hot: []`。
4. **知识库锁的操作编号查不到**：空间被未结操作锁住时，预览接口只返回 409 文案，没有操作编号，也没有接口能查当前锁定的是哪一条操作。前端目前的兜底是把最近一次确认的编号存在本机浏览器里。建议在 409 里带上 `operationId`。
5. **仍然没有接口的按钮**：这些都显示为待实现按钮或禁用输入框，并写明原因，不假装保存：
   - 时间线异常的人工裁定；
   - 手写主线需求；
   - Voice 转需求；
   - 新建项目；
   - 新开战役；
   - 战役复盘；
   - brief 附件；
   - 从数码世界导入参考；
   - NAS 原图与沿用。

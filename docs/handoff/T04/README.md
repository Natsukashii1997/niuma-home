## 使用方式

1. 本机已有 Node.js 24、项目依赖与已登录的 Codex CLI。本次验证版本为 `codex-cli 0.160.1`，未安装新依赖、改账号或选择模型。
2. 按项目原有方式构建、启动工作台，进入侧栏「Agent」的助手页，选「文案助手」，填写消息，按 Enter 或「发送」。Shift+Enter 换行；输入法候选确认不会误发。
3. 「新建助手」填写名称、预设说明 → 预览保存 → 确认保存。首次发消息才创建独立 Codex 会话。
4. 「导入 Codex 会话」按名称筛选，核对更新时间和原目录，勾选 → 预览导入 → 确认导入。已绑定的会话置灰；不复制、迁移或清空历史。
5. 「编辑助手」同样预览后确认。名称修改即时体现在工作台；预设说明仅在首次创建 Codex 会话时传入。已有会话继续使用创建时的说明。本单没有重置/新开同一助手会话接口；需要新说明立即生效时，新建另一个助手。文案助手初始说明留空，待用户填写。
6. 连接、额度、登录或会话占用错误显示在聊天框旁，输入保留。先点「重新读取历史」核对，再决定是否重新发送；系统不会自动重发。原 Codex 客户端仍占用写入权的会话可能无法续聊，先在原客户端结束占用，工作台不会抢占或偷偷 fork。

安全自检（仅验证代码，隔离数据，不调用真实模型）：

```sh
WORKDESK_DATA_DIR=$(mktemp -d) npm test
WORKDESK_DATA_DIR=$(mktemp -d) npm run build
```

## 实现与权限

- `server/codex.mjs` 管理一个按需启动的 stdio app-server；异常退出后使本轮失败，下次请求重新启动。工作台退出会结束其子进程。
- 每次新建/恢复固定 `sandbox: read-only`、`approvalPolicy: never` 并回读检查。每轮固定只读、无网络沙箱策略和 `environments: []`；新建也禁用执行环境与动态工具。工作台自身负责保存助手配置、会话关联和 Codex 历史，助手没有写文件/执行命令能力。
- 关闭 shell、hooks、plugins、apps、多代理、记忆和对话无关工具。按会话原目录读取有效 MCP 名称，逐个关闭，不用空对象假装清除继承配置；所有服务端审批拒绝，未知请求失败关闭。
- `thread/resume` 会恢复本地目录环境，这是本机协议行为；它不接受 `environments` 参数。每轮 `turn/start` 再明确传入 `environments: []`，因此不把恢复阶段的环境快照误报为零；文件写入与命令仍分别受只读沙箱、关闭 shell 工具和轮次空环境约束。
- 新建/文案助手目录来自实际数据库位置下的 `assistants/<id>/`，导入恢复使用原会话目录。没有改全局 Codex 配置、模型或推理强度。
- 关闭工作台进程的记忆注入与生成，不在助手间共享应用记忆。没有擅改导入线程原有的持久记忆设置；其他 Codex 客户端如何使用该线程不在本进程保证范围内。
- 新旧历史协议均支持：`paginated` 全量分页读取，`legacy` 使用 `thread/read`。只显示用户/助手消息，不显示推理及工具输出。
- SSE 为 `delta {text,itemId}`、`done {}`、`error {error}`。按线程和轮次过滤、处理先到通知；断开时请求中断，确认轮次结束后才放开发送锁，10 秒未确认则关闭连接。非正常结束不伪装为 done。
- 新建、编辑、导入均预览确认后才调用写接口；批量导入在单事务中按线程 ID 去重。消息正文即发送前预览，点击发送或 Enter 为明确确认。

本机生成协议是实现依据；参考 [官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)、[配置说明](https://learn.chatgpt.com/docs/config-file/config-reference)、[0.160.1 工具注册源码](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/tools/spec_plan.rs)。协议中部分字段为实验能力，未来升级 CLI 后需重新验证，不承诺跨版本兼容。

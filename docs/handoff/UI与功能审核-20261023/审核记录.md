## 一、确认的问题（按建议处理顺序）

1. **跨站请求防护只覆盖知识库收藏 5 个接口。** `server/kb-collect-pairing.mjs` 的 `guard`（Host 白名单 + Origin 必须等于页面同源，扩展只放行带配对码的 kb 路由）写得对，但只挂在 `/api/v3/kb/collect*`。其余 POST 没有校验，`readJson` 也不限制 content-type，浏览器里任何网页都能向 `127.0.0.1:5280` 发「简单请求」POST 触发：`/api/v3/timeline/sync`、`/api/v3/mentor/refresh`、`/api/v3/projects/sync`（拉飞书），`/api/assistants/:id/messages`、`/api/v3/mentor/…/answer`（消耗本机 Codex 额度），`/api/assistants`、`/api/assistants/import`、`/api/materials`（直接写库），`/api/v3/briefs/:month/autosave`。两步「预览 → 确认」的接口因为响应读不到 previewId 而安全；PUT / PATCH / DELETE 会被预检拦住。建议把 `guard` 的 Host + Origin 校验提到 `server/index.mjs` 对全部 `/api/` 生效（kb 路由保留扩展分支），同时 `readJson` 要求 `content-type: application/json`。
2. **L-03 同类遗留：`src/modules/marketing/PlansView.jsx:78`** 对 ISO `savedAt` 直接 `slice(5, 16)`，原文框显示「10-19 02:11 录入」是 UTC（北京时间应为 10:11）。每周整理试跑第 3 条已提出；收尾时看到另一个会话已在同一工作区改它（`beijingTime` + 样式机检 + 测试，未提交），本轮不再重复，等它提交后核对即可。
3. **带教答疑每次打开都等 3.7 秒。** `curl /api/v3/mentor` 实测 `3.66s`（其余 10 个只读接口都在 30ms 内），页面上是「读取带教日志 16%」进度条。`mentor.mjs` 虽有 `v3_snapshots` 的 `mentor` 快照，但 `list()` 走的 `read()` 没有先返回快照。建议和品牌页一样：先回快照、后台刷新、页面显示「正在更新」。
4. **日/周报缓存只在内存。** `reports.mjs` 的 `entry.cache` 不落库，服务重启或发布后第一次打开要等飞书读完（实看 >3 秒进度条）；其他来源都进 `v3_snapshots`。建议报告也落库快照，走已有的 staleWhileRevalidate。
5. **同一接口在一个页面里重复请求。** `useApi` 没有去重和共享：月度促销页打开一次请求 `/api/plans` 4 次、`/api/promos` 2 次；首页 `/api/v3/codex-reset` 横条和卡片各一次、`/api/v3/home/todo` 多次；自言自语按钮和抽屉各读一次 `/api/v3/selftalk`。本机延迟小，但遇到第 3 条那种慢接口会成倍放大。建议 `useApi` 加「同 path 进行中请求合并 + 几秒内复用」，或在 App 层把 plans / promos / todo 读一次往下传。
6. **像素溶解转场偶发停在遮盖帧。** 本次第一次从首页切到「策略」时主区整片空白（连页头都没有），3 秒后仍空；之后两次同样操作正常，未能复现。`dissolve` 用 `setInterval` 三帧，窗口被遮挡或定时器降频时可能停在第 2 帧（整片 `--bg` 色盖住）。建议加兜底：开始后 500ms 无论帧数都强制揭开并隐藏画布；`visibilitychange` 回到可见时也揭开。
7. **设计 Brief 删物料用了原生 `window.confirm`**（`BriefView.jsx:139`）。全站其余写操作都走 WriteBox「预览 → 确认」，视觉规范也不允许浏览器原生弹窗。建议换成 WriteBox 或 `Modal`。
8. **控制台每次进首页 / Voice 都有 `/api/v3/voice 503` 报错。** 设计上用 503 + 错误码表示「来源未接通」，页面处理正确，但会把真正的错误淹没在红字里。可选：改为 200 + `state` 字段，或前端先看 `/api/v3/status` 再决定是否请求。

## 二、功能与版面建议（需用户定）

9. **月份默认值不一致。** 月度促销默认当月（10 月），而首页「11 月促销」按钮、用户策略、设计 Brief、营销战役、交付月卡都按交付月（11 月）。工作节奏是「本月准备下月」，建议月度促销也默认交付月，保留「本月」一键切回。
10. **首页信息优先级。** Codex 重置预警同时占顶部横条和首页左上最大的卡（col-8）；交付月卡显示 0/5、8 天截止，却排在第二行。建议首页卡降为一行摘要（横条保留），交付月卡上移并按剩余天数着色（≤3 天琥珀，状态栏已有这条规则）。
11. **待我处理卡放不下。** 条目文字是「项目名 · 节点 · 负责人 · 逾期 N 天」一整段，col-4 里折 3 行，只放得下 2 条，其余 18 条收进「还有」。建议主行只放节点名，项目名与负责人放次行小字，能放 4～5 条。
12. **「转为主线需求草稿」没有去处。** Voice 和自言自语都能转，转出的草稿页面上看不到（REQUIREMENTS 已记）。按 AGENTS 规矩推荐「补上查看位置」：用户策略页「3 机会收敛」下加「待采纳草稿」一栏，或附录里列出。
13. **三个长期占位。** 项目看板「待设计」、价格档案「定价模拟器 待设计」、用户策略「导出到飞书」灰按钮（T13）。建议要么排期，要么先从页签 / 按钮里藏掉，别每次都看到。

18. **无障碍小项。** 4 处 `icon-btn` 只有 `title` 没有 `aria-label`（`AssistantsPage.jsx:94`、`PromosView.jsx:125`、`BriefView.jsx:133`、`BriefView.jsx:206`）。行内 `style` 62 处多为甘特 / 地图的动态定位，可接受。

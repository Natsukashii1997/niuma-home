## 操作方法

现有依赖可直接使用，无需安装新库。在项目目录执行下列命令，始终使用新建的临时数据目录；不要省略 `WORKDESK_DATA_DIR`：

```sh
WORKDESK_DATA_DIR=$(mktemp -d) npm test
WORKDESK_DATA_DIR=$(mktemp -d) npm run build
WORKDESK_DATA_DIR=$(mktemp -d) PORT=5290 npm start
```

1. 打开 [隔离工作台](http://127.0.0.1:5290)，进入「营销 → 方案 → 月份及业务线」。也可直接打开 [2026-09 大学辅导](http://127.0.0.1:5290/#/marketing/plans/2026-09/%E5%A4%A7%E5%AD%A6%E8%BE%85%E5%AF%BC) 或 [2026-09 国际课程](http://127.0.0.1:5290/#/marketing/plans/2026-09/%E5%9B%BD%E9%99%85%E8%AF%BE%E7%A8%8B)。
2. 复制 `fixtures/` 下对应原文并粘贴，点击「解析预览」。确认 SKU、四项字段、旧值高亮和将删除的 SKU；此时尚未写库。
3. 未识别行、重复 SKU、板块不一致或缺少板块时，按警告修改原文，再解析。改动后旧预览立即失效。
4. 点击「确认入库」。看到具体写入/更新/删除行数且预览均为「无变化」，表示数据库回读已核对。返回方案墙可看到「已录入原文」。首页仅显示本月方案。
5. 再次进入同一方案会载入原文；点击「复制原文」。整份富文本粘贴保留 HTML 和纯文本，局部编辑退回纯文本；粘回飞书的排版以实际表现为准。

如果显示「入库结果未确认」，先点「重新载入核对」，检查已经保存的原文，再决定是否重新解析；系统不会自动重复写入。复制失败时检查浏览器剪贴板权限，或在文本框内全选复制。测试服务结束后在终端按 Ctrl+C。

## 验证结果

- `npm test`：15 通过，0 失败（使用上方隔离环境变量）；`npm run build`、`git diff --check` 通过。
- 纯函数覆盖两个样例、编号/空项/英文冒号、未识别行、未知与混合板块、同业务线别名、重复 SKU、点号名称和小数列表。大学辅导 6 行，国际课程 1 行，国际课程新签 1 行、续费 2 行。
- HTTP 测试验证预览不写库、同月优先与最近历史月回退、原文保存、按组覆盖删除、重复确认不增行、错误请求不写入，以及 SQLite 触发器在第二行故障时整笔回滚。
- 浏览器用真实剪贴板粘贴两个 fixtures，验证双格式/纯文本复制、修改后重新预览、错误门禁、实际删除及写后回读失败的恢复路径。结果见 [浏览器验证.json](浏览器验证.json)。大学辅导的 HTML 为测试包装，验证剪贴板格式通路；未宣称真实飞书客户端回贴验收。
- 1680px 与 820px 页面已截图检查；窄屏无页面整体横向溢出，浏览器无运行时异常。只读子代理复核发现的点号/小数误解析已修正并再次静态确认。
- 首败记录：解析模块尚未实现时测试失败，国际课程列表/别名及点号/小数回归分别先失败再通过；接口由 501 失败推进到通过。首次 HTTP 启动被沙箱限制回环监听，获工具审批后正常运行。浏览器首轮因测试脚本把追加行号写成 24 而停止（fixture 末尾已有换行，实际 25），改用文本行数计算后，在全新隔离库重跑通过。
- 默认真实数据库 SHA-256 操作前后一致；本轮只在临时数据目录写入，验收服务已停止。

## 需校准的验收口径

「论文稳Pass」在 fixture 第 23 行写为 `正价：全款立减¥1000`，旧库却保存为正价「无」、新签活动「全款立减¥1000」。本实现遵从固定规则，预览同时高亮正价与新签活动，不能满足派单中未列例外的“与库逐字段一致”。两个事实来源均未修改，请 Claude 校准验收表述后验收。

接口与骨架没有偏离，没有新增依赖。整份粘贴的 HTML 保留；局部编辑后的富文本重建不在本轮实现范围。T02 促销表视图及其他派单保持原状。

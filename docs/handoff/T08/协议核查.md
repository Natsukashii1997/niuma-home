## 已由用户确认的语义

- `docs/API.md` 助手节以及 T08 范围第 1、2 条把数据库 `model / effort = null` 定义为“跟随 Codex 默认配置”或“恢复默认”。
- T08 范围第 2 条同时规定：没设置就不向 `turn/start` 传这些字段，沿用会话现有设置。
- 协议明确显式参数会影响后续轮次。因此“先选择模型 B 并对话 → 清空工作台设置 → 再发消息”的路径，仅省略参数无法保证回到 Codex 全局默认。下拉框可能显示“跟随默认”，runtime 却仍为 B。

这是派单内部行为与文案的冲突，不是字段名不匹配。首次核查已暂停代码实现并写入 CURRENT；用户随后在当前会话选择“恢复 Codex 全局默认”，构成本轮新执行基线。API 路径和数据形状不变；派单中“没设置就不传”及对应验收条款需由 Claude 按此决定同步。

校准后的实际规则：

1. 数据库两列仍保存 `null` 表示跟随默认，不把读取到的默认值固化进数据库。
2. 下一条消息读取 `config/read({ includeLayers: false })`，省略 `cwd` 以排除导入会话原目录的项目配置层。只取模型和推理强度，不保存、输出完整配置，也不修改配置文件。
3. 配置未指定模型时取 `model/list` 的 `isDefault` 项；未指定强度时取该模型的 `defaultReasoningEffort`。显式选择模型、强度为空时，同样取该模型的默认强度。
4. 无法解析默认值、模型不可用、强度不受支持、配置读取失败时返回明确错误，阻止该轮发送。
5. 每轮向 `turn/start` 明确传入解析后的模型与强度，撤销上一轮模型选择对本轮的延续影响。始终保留原有只读沙箱、`approvalPolicy: never`、空执行环境和禁用工具约束。
6. runtime 从 `thread/resume` 响应获取；保存设置不提前伪造生效值，下一轮结束后重新回读。

独立只读源代码复核确认：`config/read` 省略 cwd 时使用[非项目配置加载路径](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/config_manager_service.rs#L112-L165)；有效配置包含该 app-server 进程选择的 [profile-v2 层](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/config/src/loader/mod.rs#L271-L318)。本工作台未传 `--profile`，不会自动继承另一客户端临时选择的 profile。这里“全局默认”指本机 app-server 的非项目有效配置，不是其他会话的临时选择。

真实隔离对话已经验证：最初默认 `gpt-6-astra / ultra` → 选择 `gpt-6-luna / high` 并正常回复 → 清空设置 → 下一轮回到 `gpt-6-astra / ultra` 并正常回复；每步 runtime 均与协议响应一致。摘要见 `验证记录.json`。

## 官方能力核查与边界

以下是官方文档证据，与上述 UI 亲测区分：

- 桌面端／网页版支持批量操作，Shift 点击目录标题进入、Esc 退出；目录批量操作最多主动选择 50 页，选中父页的子树跟随。见[批量操作知识库页面](https://www.feishu.cn/hc/zh-CN/articles/763992129311-批量操作知识库页面)。本轮未做上限压力验证。
- “迁入已有云文档”一次最多选择 20 个，与目录批量操作的 50 项不是同一入口。迁入后的权限会受到目标父页面继承规则影响，原位置继承协作者的权限取消；不能承诺迁移一定不影响同事访问。见[移动云文档到知识库](https://www.feishu.cn/hc/zh-CN/articles/874534846817-移动云文档到知识库)。本轮未实际迁入或迁出。

## 工作台需求建议（待用户整体校准）

1. **文档工作清单**：完整标题、原位置、类型、更新时间、简要内容和读取状态放在同一处，方便筛选、比较、选择。保留现有分类和原链接；不要在接入时自动复制所有正文或附件。
2. **分类草稿**：先记录准备如何归类，可暂存、撤销、继续处理。专题／标签允许同一文档服务多个工作事项；真实移动与个人标签分开。AI 给出理由和内容依据，用户可改判，不能依据标题直接去重。
3. **逐项变更预览**：显示旧位置到新位置、改名、涉及子页面和可核实的权限影响；用户选择采纳的部分。源内容或目录已变化时重新核对，预览不能无限有效。
4. **确认后同步并回读**：记录每项成功、失败、结果未知及下一步。批量执行不等于跨系统单事务；不先承诺一键恢复。权限调整、删除、正文合并与改写另行明确范围。

候选验收场景：用户选定一批真实文档，能理解它们是什么、为什么归到一起、有哪些待判断关系，保存并调整整理草稿；只对确认部分同步，最后能核对实际变化及未完成项。收益需由真实使用验证，不能以新增清单页或操作按钮证明。

当前不扩展为全库治理方案，也不制定正式 API／派单。具体整理动作优先级、内容读取范围、更新与冲突处理细则、实际 API 写入可行性留待需求校准后核查。

# 活动价格测算台：业务需求草案 v0.1

日期：2026-10-15

状态：已记录用户明确决定；建议能力与整份需求范围待用户校准。本轮只梳理需求，不开发。本文不是派单、技术方案或已生效的价格规则，不替代 REQUIREMENTS.md、docs/API.md。

## 1. 核心需求复述

常浩负责公司价格制定与活动价格测算，希望在个人工作台直接调整条件并查看计算结果，帮助比较和选择活动价格方案。
测算同时覆盖客户价格、公司成本与毛利；成本口径、价格底线和最终取舍由常浩确定。
使用体验要比当前表格更直观、美观、便于比较；现有表格可以调整，不要求复刻它的行列结构。
成功应体现为：看得懂输入和计算依据、改参数能看到影响、能比较方案并识别触及底线的位置。
本轮产出为这份需求草案；尚未确认的能力和业务规则明确列出，不据此启动开发或发布价格。

## 3. 建议的使用过程（待确认）

选择业务线与产品/课时档位 → 选择比较基准 → 调整价格和活动条件 → 查看价格、成本、毛利及底线提示 → 对比候选方案 → 保存选定方案与理由。

这是未来产品的使用过程建议，不是本轮开发任务。主要使用者按现有个人工作台定位为常浩；协作编辑、审批和对外报价不自动纳入。

| ID | 能力 | 需要解决的实际问题 | 预期可见结果 |

| A03 | 多档位测算 | 一次活动涉及多个课时包，既要看单档也要看整体梯度 | 同屏查看各档位的总价、实际单价、优惠及毛利，标明非预期的梯度变化 |

| A07 | 与正式促销信息衔接 | 防止试算数字被误当成正式售价 | 明确区分测算草稿与已选方案；写入促销表或对外发布须另定流程、单独授权 |

“丰富”优先体现为比较、解释、试算和追溯能力；动画、图表数量和装饰本身不作为完成标准。图形类型与页面布局在需求确认后再设计。

## 5. 输入、输出与业务规则

### 5.1 价格与活动条件

建议输入包括：业务线、产品或服务、地区（适用时）、活动名称、课时/数量档位、基准价格、活动售价、折扣或减免、赠送课时/权益。

- 不同产品的计价单位可能不同，不预设公司所有产品都按课时计价。
- 直接填写售价与填写折扣时，须明确哪项驱动计算，避免两者矛盾而同时生效。
- 价格、赠课与其他权益不能一律直接相减；赠品价值、实际成本和现金优惠需要区分。
- 若支持多种优惠叠加，生效顺序、可叠加范围、互斥规则必须有用户确认的定义。
- 人数、成交量、转化率等经营预测尚未纳入已确认范围，不能以假设销量包装实际收益。

### 5.2 成本口径

应允许使用常浩确认的成本项目、计费依据和版本。可供讨论的项目形式包括：按实际提供课时、按订单固定金额、按收入比例、其他明确的分摊方式；这些仅为候选形式，不是已确认成本清单。

每项成本需说明：名称、单位、金额或比例、计费基数、是否适用于赠课/赠品、适用业务与产品、有效版本。哪些成本计入毛利、哪些另行展示，由常浩确定。

需要特别明确：赠送课时是否具有同等服务价值、按赠送量还是预计使用量计成本、成本是否已被其他项目包含。未知成本须显示“未完整配置”，不能默认为零或展示成已确认的高毛利。

### 5.3 结果与公式口径

| 建议展示结果 | 定义要求 |
|---|---|
| 客户实付金额 | 按选定优惠规则得出；与收入计算基数的关系须明确 |
| 实际课时/单位价格 | 实付金额除以明确的可用服务数量；赠送服务是否进入分母须说明 |
| 优惠金额与幅度 | 标明相对于哪个基准及其版本；跨服务内容不能直接当成等价优惠 |
| 测算成本及构成 | 按所选成本口径逐项计算，可以查看具体组成 |
| 测算毛利额与毛利率 | 建议表达为“测算收入基数－纳入的成本”“毛利额÷测算收入基数”；收入基数、纳入项及税费处理由用户定，不将其直接称为净利润 |
| 与基准/其他方案的差异 | 区分总价、单位价格、优惠、成本、毛利额、毛利率的变化；毛利率差使用百分点 |
| 距底线的余量 | 明确比较的是总价、单位价格、毛利额还是毛利率，以及触发条件 |

以上为待确认的公式语义，不是对原表公式的核验结论。货币、含税/未税、四舍五入位置和精度、百分数显示、零分母规则需在正式公式确定时一起定义。展示用的取整结果不应悄悄改变实际计算基础。

### 5.4 底线与适用范围

价格底线由常浩提供。待定内容包括：按业务线/产品/地区/档位设置，使用哪种指标，是否有活动例外，以及低于底线时只提示还是禁止定稿。不预置行业阈值、不替用户判断某个历史价格已经获批。

比较时应明确产品、服务数量、地区、货币、成本版本与活动条件；口径不一致时标明差异，避免给出没有可比性的优劣结论。

## 6. 使用体验与数据可信度（建议验收方向）

- 输入项、自动计算结果、历史基准在视觉和文字上可区分；修改后看到当前结果及与修改前/基准的差异。
- 关键结果不依赖横向寻找单元格，重点呈现售价、实际单价、成本、毛利与底线状态。
- 图表和表格使用同一份计算结果；可查看构成和公式依据，而不只显示红绿标签。
- 多档位和多方案比较保持单位、时间、基准一致；页面沿用工作台已有风格，具体位置与布局待确认。
- 成本或规则缺失、零数量/零收入、无效输入、冲突优惠、保存失败应给出可理解提示，不能静默产出零值或“通过”。
- 修改成本或底线后，历史已保存结果应能按当时口径解释；是否生成新版本、是否重算旧草稿需明确。
- 若未来读取飞书或其他外部基准，读取失败要显示失败/更新时间，不能将旧数据伪装成最新价格；本轮未决定采用同步。

## 7. 明确暂不做与尚未承诺的能力

- 本轮不开发代码、接口、数据库或原型，不改变正式 5280 服务、真实数据、飞书表格与公司价格。
- 不替常浩制定实际成本、利润目标、价格底线或自动选择正式价格。
- 飞书表作为现状参考；是否继续维护、导入哪些内容、是否同步均未确定，不默认双向同步或自动迁移全部历史表。
- 自动发布到促销表/飞书、生成报价单或价格物料、审批、多用户协作、销量预测、利润最大化或 AI 自动定价均未确认，不纳入当前需求基线。
- NAS 物料需求单独保留在 CURRENT.md，等待用户提供目录；不是价格测算的前置依赖，本轮不继续该接入。

## 9. 初步验收依据（随需求确认调整）

1. 用户提供一组代表性产品、活动参数及成本口径后，价格、成本、毛利的计算能逐项解释并与人工核对结果一致。
2. 修改售价或赠课等一个参数，能看见受影响结果；成本缺失与无效输入不会产生看似可信的完整结论。
3. 如采纳方案比较，可在统一口径下回答“哪个方案客户优惠更大、公司毛利怎样变化、是否触及用户设定的底线”。
4. 如采纳留档，可恢复一次测算的输入、规则版本、结果和选择理由；之后修改规则不会掩盖当时依据。
5. 试算与正式价格有清楚边界，用户未确认发布的候选价格不会自动进入正式促销信息。
6. 常浩能在工作台独立完成代表性测算和比较，不需要看公式代码或让技术人员代为改参数；直观性与视觉由常浩实际使用验收。

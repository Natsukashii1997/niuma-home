# 09 · 反例测试集 `cases-v1`

把「专业严谨」写成可验收的行为。每个场景给出构造方法、期望结果和由谁负责拦截。批 1 起，「代码」层的场景写成 `npm test` 里的自动化测试；「skill」层的场景写进 skill 的 evals，并作为复审评测样例。

**负责层**：
- **代码**：工作台的解析、窗口计算、校验器、写入契约，确定性拦截。
- **skill**：生成时就不能犯；万一犯了，代码层的不变量是第二道防线。

## 复审能力评测（批 2）

从批 1 技术试跑的结果里取一份，制作两类样例：

- **有缺陷样例**：注入至少 5 种缺陷，例如把一个日期改错、在需求和购买之间制造跳步、给不适用的时间窗配早鸟价、删掉一个 P0 机会的反驳、把管理判断写成已验证需求。复审必须发现全部缺陷，并定位到对象 ID。
- **无缺陷样例**：经常浩确认没有关键问题的一份。复审不能无依据地挑出关键问题（措辞建议不算）。

两类样例都通过，才算复审能力合格。

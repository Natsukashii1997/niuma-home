# 02 · 障碍体系 v2 与促销目标 `barrier-v2.1`

决策障碍回答「学生为什么可能不采取购买行动」。它是商业决策链上的判断，和学业痛点分开：痛点是完成学业任务的阻力，障碍是选择我们的阻力。

## 1. 设计原则

1. **v2 是新方法论的完整体系**，覆盖新签和续费；旧 A1–C1 只是兼容映射，不是分类上限。
2. **有依据才写**：没有依据的障碍写成 `status=unknown` 的 Claim（附 gap、route），不为了触发促销规则而创造障碍。
3. **新签、续费独立研判**：续费不沿用新签的障碍；不默认老学员没有信任障碍。
4. **促销目标不由障碍自动决定**：目标由「机会 + 障碍 + 目标人群」共同研判，本文的映射只提供候选。
5. **障碍是购买行为判断，要有行为证据**：时间位置、学校政策这类客观事实只能作情境依据，不能单独证成障碍（第 2.3 节）。

## 2. 障碍清单

编码规则：`BR-` + 大类字母 + 序号。大类按 COM-B 组织：**M** 动机（Motivation）、**C** 能力（Capability）、**O** 机会与触发（Opportunity）、**F** 适配（Fit）、**R** 续费专属（Renewal）。

| 编码 | 障碍 | 判定要点（什么情况下算这个障碍） | 适用人群 | 旧编号 |
|---|---|---|---|---|
| `BR-M1` | 没意识到需要 | 学生未把当前学业任务和外部辅导联系起来 | 新签 | A1 |
| `BR-M2` | 觉得还来得及 | 节点在行动窗口之外或刚进入，学生倾向推迟决定 | 新签 / 续费 | A2 |
| `BR-M3` | 不信任辅导效果 | 怀疑辅导能否带来实际帮助，或怀疑老师水平（一般性的不信任，不以本人既往服务体验为依据） | 新签 / 续费 | A3 |
| `BR-M4` | 有替代方案 | 用学校资源（Office Hour、写作中心）、同学、AI 工具替代 | 新签 / 续费 | A4 |
| `BR-M5` | 学术诚信顾虑 | 担心辅导或使用外部帮助被学校认定为学术不端（如学校收紧 AI 使用规则） | 新签 / 续费 | —（新增） |
| `BR-C1` | 嫌贵 | 价格超出预期，或在等折扣节点（如双 11、黑五） | 新签 / 续费 | B1 |
| `BR-C2` | 怕选错 | 不知道该选哪个方案、班型或老师 | 新签 / 续费 | B2 |
| `BR-C3` | 没时间 | 多任务叠加，担心辅导占用复习时间 | 新签 / 续费 | B3 |
| `BR-C4` | 需要家长同意 | 付款或决策需要家长参与 | 新签 / 续费 | B4 |
| `BR-O1` | 没被触达 | 不知道我们能帮，或没在需要时看到我们 | 新签 | C1 |
| `BR-F1` | 方案不匹配任务 | 现有产品覆盖不了学生当下的具体任务（科目、时段、形式、交付周期） | 新签 / 续费 | —（新增） |
| `BR-R1` | 上阶段体验或效果一般 | 已购学员**基于既往真实服务体验**，对上一阶段服务不满意或感知收获不足 | 续费 | A3（近似） |
| `BR-R2` | 下阶段没有明确任务 | 已购学员看不到下一阶段还需要什么帮助 | 续费 | A1（近似） |
| `BR-R3` | 导师或课程衔接不上 | 原导师不可约、课程内容不接续 | 续费 | —（新增） |
| `BR-R4` | 已有余量 | 课时、权益还没用完，暂无追加购买的必要 | 续费 | —（新增） |
| `BR-R5` | 续费价格无优势 | 老学员价格和新客相同或更贵 | 续费 | B1（近似） |

- 「适用人群」只写「续费」的，不能出现在 `targetRelation=新签` 的 Claim 上；反过来，「只写新签」的不能出现在续费上。校验器按此拦截（Schema v2 不变量 I-11）。`targetRelation=通用` 的 Claim 只能用新签、续费都适用的障碍。
- 「旧编号」标「近似」的，只用于让打法卡能关联到这个障碍，语义不完全相同；正文和论证里一律用 v2 的名称。

### 2.1 多标签与主障碍

同一情境、同一目标人群（`targetRelation`）下，障碍可以多个并存（多标签），但必须指定**一个主障碍**，其余为辅助障碍，对应 Claim 的 `barrierRole=primary / secondary`（Schema 3.3）：

- 主障碍：对这群学生当下不购买影响最大、方案要优先解决的那一个。选定理由写进该 Claim 的 `rule`。
- 辅助障碍：同时存在、方案可以兼顾的障碍。
- 只有一个障碍时，它就是主障碍。证据不足以判断谁更主要时，主障碍按证据较强的一条定，并在 limitations 里写明「主次依据不足」。
- 没有障碍 Claim 时，不强造主障碍。全部障碍都是 `unknown` 时，主障碍只表示待验证的研究重点，不能据此升级促销推荐（Schema I-08 仍按各障碍的 status 判定）。
- 促销 Strategy 的主要目标从主障碍的候选目标里选；只针对辅助障碍的方案只能作辅助方案。

### 2.2 相近障碍判定表

下面六对障碍容易混淆。判定时先查清「需要区分的事实」，事实不清就写 `unknown`，不在两个之间凭印象挑一个。

| 相近障碍 | 需要区分的事实 |
|---|---|
| `BR-M1` 没意识到需要 ↔ `BR-R2` 下阶段没有明确任务 | 学生是新签还是已购；已购学员的问题是「看不到下一阶段要做什么」（R2），新签学生是「没把当前任务和辅导联系起来」（M1） |
| `BR-M2` 觉得还来得及 ↔ `BR-C1` 嫌贵 | 推迟的原因是时间判断（节点还远）还是价格（在等折扣节点、嫌价格高）；有等折扣行为的归 C1 |
| `BR-M3` 不信任辅导效果 ↔ `BR-R1` 上阶段体验或效果一般 | 不信任是否来自本人既往真实服务体验：有，归 R1；没有（一般性怀疑、听说、对行业的印象），归 M3 |
| `BR-C3` 没时间 ↔ `BR-F1` 方案不匹配任务 | 学生是没有可用时间（任务叠加），还是有时间但现有产品的时段、形式、交付周期对不上；后者归 F1 |
| `BR-F1` 方案不匹配任务 ↔ `BR-R3` 导师或课程衔接不上 | 是产品本身覆盖不了新任务（F1），还是产品有、但原导师不可约或课程内容不接续（R3）；R3 只用于续费 |
| `BR-C1` 嫌贵 ↔ `BR-R5` 续费价格无优势 | 是绝对价格超预期（C1），还是老学员价与新客价比较后觉得没有优势（R5）；R5 只用于续费 |

具体判定示例在延期事项中补充（见 [README](README.md)「延期事项」）。

### 2.3 购买行为的证据要求

障碍回答的是「学生为什么不买」，属于用户决策行为。证据按下面的上限处理：

1. **客观事实只作情境依据**：节点在日历上的位置、学校政策、学期安排等，能说明学生所处的情境，不能单独证明学生已经产生某种购买顾虑。
2. **`BR-M2`、`BR-M5` 仅凭客观事实时写 `unknown`**：只有节点位置（M2），或只有学校政策（M5，学校收紧 AI 规则不等于学生已有顾虑）时，status 为 `unknown`，gap 写缺少的用户行为证据，route 指向可补的已登记来源（如 `SRC-bizcard` 的业务观察、`SRC-voice`）。
3. **其他障碍只有常识依据时，最高 `inferred` + `weak`**，limitations 写「缺少用户决策行为证据」。按 Schema I-08，这样的障碍最多支撑「附条件推荐」。
4. 能把障碍提到 `inferred + partial` 或 `known` 的，是用户决策行为证据：业务背景卡里的事实记录或业务观察（咨询、成交、流失、续费的情况）、Voice 里的学生原话等。

## 3. 和打法库的关联

47 张打法卡的元信息行仍用旧编号（如 `障碍 A2 ; B1`）。批 1、批 2 不重新给卡打标签，按下面的规则关联：

1. 一个 v2 障碍的「候选卡」= 元信息里主障碍或辅障碍包含它的旧编号、且阶段与 `targetRelation` 相容的卡（新签栏用「新签 + 通用」，续费栏用「续费 + 通用」）。
2. 旧编号为空的障碍（`BR-M5`、`BR-F1`、`BR-R3`、`BR-R4`），没有自动候选卡。研判时可以从打法库里手工提名，但必须在论证里写明这张卡怎样作用于该障碍；也可以判断「促销不是这个障碍的主要解法」，改为在用户策略里提出服务或产品方向（例如学术诚信顾虑靠服务边界说明，不靠让利）。
3. 打法卡以后如果改用 v2 编码，升本文件版本，并同步更新本节。

## 4. 促销目标

### 4.1 七个目标

| 目标 | 要解决的用户决策问题 |
|---|---|
| 需求唤醒 | 不知道自己是否需要服务 |
| 信任建立 | 担心辅导质量与匹配 |
| 降低行动门槛 | 对购买步骤或方案选择有顾虑 |
| 时间促进 | 有需求，但没有及时行动 |
| 价值增强 | 认为产品价值不足 |
| 续费承接 | 需要衔接下一学习阶段 |
| 扩科发展 | 出现新的学科需求 |

### 4.2 障碍 → 候选目标（只提供候选）

| 障碍 | 候选目标（排序不代表优先） |
|---|---|
| `BR-M1` 没意识到需要 | 需求唤醒 |
| `BR-M2` 觉得还来得及 | 时间促进；需求唤醒 |
| `BR-M3` 不信任辅导效果 | 信任建立；降低行动门槛 |
| `BR-M4` 有替代方案 | 价值增强；信任建立 |
| `BR-M5` 学术诚信顾虑 | 信任建立（主要靠服务边界说明，促销作用有限） |
| `BR-C1` 嫌贵 | 价值增强；降低行动门槛 |
| `BR-C2` 怕选错 | 降低行动门槛；信任建立 |
| `BR-C3` 没时间 | 降低行动门槛；价值增强 |
| `BR-C4` 需要家长同意 | 信任建立 |
| `BR-O1` 没被触达 | 需求唤醒（主要靠渠道和触达动作，不靠让利） |
| `BR-F1` 方案不匹配任务 | 价值增强；扩科发展 |
| `BR-R1` 上阶段体验一般 | 信任建立；续费承接 |
| `BR-R2` 下阶段没有明确任务 | 续费承接；需求唤醒 |
| `BR-R3` 导师或课程衔接不上 | 续费承接 |
| `BR-R4` 已有余量 | 续费承接；扩科发展；或结论为「暂不推动续费」 |
| `BR-R5` 续费价格无优势 | 续费承接；价值增强 |

研判选定目标时，必须写明：为什么是这个目标而不是其他候选；它对应哪个机会、哪个目标人群。同一张打法卡可以服务多个目标，方案里只写一个主要目标。

## 5. 与基线 `baseline-v1` 的差异处理

现有 `matchPromo`（障碍计分 → 查优先表选卡）冻结为 `baseline-v1`，代码和输出都标版本号，之后不再修改。新方案与基线不同之处，按四类记录：

| 差异类型 | 记录要求 |
|---|---|
| 新增时间限制排除了基线打法 | 写明哪条时间条件、哪个窗口排除了它 |
| 新签、续费独立研判导致不同 | 写明新的用户依据 |
| AI 提出了更合适的候选 | 比较两者的目标匹配、证据和适用条件 |
| 旧数据无法映射到新结构 | 标「不可比较」，不强行解释 |

基线只提供可解释的参照，不决定新方案是否正确。

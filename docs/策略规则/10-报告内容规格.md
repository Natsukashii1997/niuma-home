## 1. 四个价值标准

所有结构和写法都服务于这四条。

| 标准 | 要回答 | 判据 |
|---|---|---|
| 可读性 | 能不能快速看懂这个月发生了什么 | 读前 1–2 分钟（第一章），能形成清晰的月度整体认知 |
| 洞察力 | 有没有发现事实背后的商业意义 | 不是「考试前学生可能需要复习」，而是解释这个阶段的学生在争取什么、害怕什么、怎么选择、什么决定他是否愿意买 |
| 推导力 | 商业动作是否由前面的判断自然产生 | 为什么这个地区优先、为什么这类用户、为什么这个 SKU、为什么这种优惠，都能顺着因果链说出来 |
| 指导性 | 能不能直接转化为经营行动 | 营销、销售、用户运营、师资都知道本月先做什么；有选择、有取舍、有下一步 |

**详细 ≠ 琐碎**：详细是对重要问题充分展开；琐碎是对大量低价值信息同等篇幅罗列。报告可以很详细，不能琐碎。

## 2. 三层体系

| 层 | 是什么 | 产物 | 谁读 |
|---|---|---|---|
| 研究层 | SCOUT-8 阶段 01–05：事实、情境、Claim、Evidence、障碍研判 | 底稿、研判稿（结构化） | AI 自己；审计追溯 |
| 综合层 | 跨事实归纳 → 核心洞察 → 机会判断 → 策略选择 | 综合稿、商业设计稿 | AI 自己；独立审核 |
| 报告层 | 《YYYY-MM 月度用户策略报告》，八章 + 附录 | `report.md` | 常浩、各部门 |

- SCOUT-8 是 AI 的内部研究方法，**不是报告的章节结构**。Scenario、Claim、Evidence、Barrier 是中间资产，**不是报告的阅读单元**。
- 报告正文**不从 Claim 拼接**，单独写成章节与段落；正文里不出现 Claim 编号、Evidence 编号、状态码、障碍编码。

**信息分三层，不平权展示**：

| 信息层 | 放在哪 | 例 |
|---|---|---|
| 核心策略判断 | 章节正文与小结，主导阅读 | 本月主攻市场、需求方向 |
| 关键论证事实 | 正文中的必要表格和段落，承担解释 | 支撑结论的重点院校、时间节点、用户证据 |
| 完整研究依据 | 附录，负责审查和追溯 | 全部学校日期、Claim、来源、规则版本、自检 |

## 3. 报告结构

### 3.1 八章与比重

比重是正文篇幅的初始分配，试写时校准；附录不计入。正文参考总量 8,000–12,000 字（试写校准）。

| 章 | 名称 | 回答的问题 | 比重 |
|---|---|---|---|
| 一 | 月度策略总览 | 这个月到底要怎么打？ | 8% |
| 二 | 月度时间线与需求节奏 | 本月不同时间会发生什么？ | 12% |
| 三 | 六地区用户需求深度分析 | 为什么这些用户在这个月值得关注？ | 32% |
| 四 | 地区优先级与机会判断 | 资源应该优先投入哪里？ | 10% |
| 五 | SKU 与产品价值策略 | 卖什么？用户为什么买？ | 14% |
| 六 | 营销主张与促销策略 | 怎么吸引、说服和促成购买？ | 12% |
| 七 | 月度执行方针 | 各部门接下来具体做什么？ | 9% |
| 八 | 关键假设与验证事项 | 哪些判断还需要验证？ | 3% |
| 附 | 研究依据 | 判断凭什么？ | 不计入 |

比重按内容分三块：第 1–4 章「月度洞察与需求判断」62%（8+12+32+10，研究分析是报告的主体）；第 5–6 章「产品、营销与促销方案」26%；第 7–8 章「执行与验证」12%。

阅读上分三层（与比重分块不同，不要混用）：第 1–3 章「看清局势」，是策略研究最重要的基础；第 4–6 章「形成选择」，是研究向商业决策的转化；第 7–8 章「指导行动」，是策略产生实际经营价值的保障。

### 3.2 阅读顺序与研究顺序

阅读顺序 = 决策顺序：先结论，再依据，再深挖，最后落到产品、促销和执行。研究顺序相反：先查节点、挖需求，再定机会、产品和促销，**第一章最后写**。

### 3.3 每章推动论证往前走

同类信息只做一次完整论证。第二章说时间线，第三章解释用户需求，第四章比较机会，第五章判断产品，第六章设计营销与促销；后面章节只引用前文结论，并推进到新的判断，不复述。

### 3.4 共有机制只论证一次（补充）

同一种处境（如 Final 冲刺）会在多个地区同时出现。第三章按地区写时：**共有的需求机制只在最主要的那个地区完整论证一次**，其他地区写「同 X 地区，差异在于……」，只展开差异（时间、院校群、规模、例外）。跨地区的合并在第四章的机会主题里完成。

## 4. 逐章规格

### 第一章 · 月度策略总览（8%）

全报告最重要的阅读入口。不是一句话判断的扩写，而是所有研究完成后浓缩出的**月度经营判断**。三部分，顺序固定：

**1.1 月度整体定性**：一段 150–250 字的连贯文字，讲清四件事：
1. 本月在全年学业周期中的位置；
2. 各主要留学目的地的总体学业节奏（有错峰要讲出错峰）；
3. 本月需求的主要特征及变化；
4. 应该采取的总体经营方向。

要写出**阶段、变化和经营含义**，而不只是事实；要解释地区之间的差异；最后落到初步经营方针。对比：「本月多地进入考试窗口，需求活跃度高」不合格。

**1.2 本月核心策略判断**：3–5 条，不超过一屏。

| 判断维度 | 应输出 |
|---|---|
| 需求主线 | 这个月最值得经营的核心需求是什么 |
| 地区选择 | 哪些地区主攻、哪些地区提前布局 |
| 核心用户 | 主要面向哪些学业阶段及新老学员 |
| 产品方向 | 主推哪类服务价值，而不是罗列 SKU |
| **关键取舍** | 本月哪些方向暂不重点投入，以及为什么（必填） |

**1.3 本月最重要的经营目标**：业务目标已知就写明确目标；不知道就先确定**策略性质**：新增获客驱动 / 老学员续费驱动 / 紧急需求转化驱动 / 多地区处于不同经营阶段的组合策略。不编收入目标。

**不合格**：只有事实没有方向；没有关键取舍；用「可能」「或许」开头；口号化。

### 第二章 · 月度时间线与需求节奏（12%）

核心问题：整个市场在这个月的时间演变是怎样的？不同地区什么时候进入什么阶段？三层：

**2.1 全年学业周期定位**：本月对各地区分别是学期初、学期中、期末、出分及补考，还是新学期前的衔接期。学期错峰的要说明它们不处于同一周期；不能把全球市场归成一个统一的「期末季」。

**2.2 跨地区关键时间线**：一张月度时间矩阵。

| 时间段 | 主要学业事件 | 用户需求变化 | 经营意义 |
|---|---|---|---|
| （按真实转折点分段） | 按院校事件归纳 | 准备 / 过渡 / 冲刺 / 消退 | 本阶段优先承接什么、是否切换主推、为下月铺垫什么 |

- 上中下旬只是阅读辅助，**不强行平均分段**：主要变化发生在 12 日和 23 日，就围绕这两个节点分段。旬按日期算（1–10 上旬、11–20 中旬、21 日起下旬）。
- 每段都要回答「需求怎样变化」「商业机会怎样变化」，不停在「发生了什么」。
- 范围是目标月整月 + 下月前 14 天（与需求生命周期一致）。

**2.3 月度需求波次**：同样是考试需求，按时间、用户行为和服务准备判断处在哪个阶段：

| 需求阶段 | 用户关注的问题 | 策略侧重点 |
|---|---|---|
| 提前规划期 | 是否需要辅导、如何安排学习 | 需求教育、规划、提前咨询 |
| 集中准备期 | 如何安排课程和复习任务 | 方案匹配、效果证明、课程组合 |
| 考前高紧迫期 | 剩余时间能否解决核心问题 | 匹配效率、课程针对性、交付可行性 |
| 考后衔接期 | 下一阶段需要做什么 | 后续课程、学业规划、续费或新需求 |

不要求每月四个阶段都出现。生命周期窗口（T-42、T-28 等）**只是研究线索，不是学生真实行动的概率曲线**；需求阶段的转换要用咨询、购买和业务反馈验证，没有时按「待验证」标注。

读完本章，读者应能说清：本月需求为什么不是均匀分布的，哪些节点会推动需求明显变化，为什么不同地区要采取不同节奏。

### 第三章 · 六地区用户需求深度分析（32%，研究主体）

**定位**：以地区为阅读单元，以院校时间线为事实依据，以用户场景为研究核心，以商业机会判断为最终出口。

**3.1 每个地区七层分析**（是一节完整的分析逻辑，用小标题和连贯段落写，不是七张卡片）：

| 层 | 内容 |
|---|---|
| 01 地区总体判断 | 一句话：本月该地区的学业阶段、核心需求与商业机会 |
| 02 关键院校节点与地区时间规律 | 从院校事实归纳阶段分布和时间节奏（3.2） |
| 03 用户状态与关键任务 | 不同学业阶段、不同新老用户正在经历什么 |
| 04 核心需求与深层痛点 | 为什么需要帮助、最担心什么、真正想解决什么（第 5 节深挖） |
| 05 购买决策与行为机制 | 用什么标准选服务、什么推动购买、什么阻止购买、决策何时发生 |
| 06 需求强度与机会成熟度 | 四维判断：紧迫性、真实性、购买成熟度、服务可行性（第 5.5 节） |
| 07 地区策略结论 | 三项结论：本月核心用户是谁？核心需求是什么？优先承接哪种机会？ |

**写法**：每个地区的核心分析用「结论 → 论证 → 行动含义」三段式：
1. 结论：该地区本月处于什么关键阶段，最重要的用户需求是什么；
2. 论证：哪些学校节点、真实反馈、用户任务支持判断；为什么这些节点会形成这种需求；有哪些例外；
3. 行动含义：优先关注哪些用户、满足什么需求、采用何种服务价值方向。

**3.2 从院校时间线归纳地区规律**：避免两种错误：罗列学校（A 校 10 日考、B 校 15 日考……），和过度概括（「美国 12 月进入期末考试季」）。路径是**具体事实 → 院校群体聚合 → 时间分布 → 阶段差异 → 地区规律**，研究时看六个维度：

| 维度 | 观察什么 |
|---|---|
| 时间集中度 | 关键考试、作业截止是否集中在某段时间 |
| 院校覆盖 | 数据代表了哪些学校，有多少重要学校缺失 |
| 阶段差异 | 本科与研究生是否节奏不同 |
| 事件连续性 | Final 后是否衔接出分、补考或下学期 |
| 地区内差异 | 有没有明显早考、晚考或特殊院校群 |
| 数据可靠性 | 哪些日期已核实，哪些仍是推测 |

结论应类似：「在已覆盖院校中，主要节点集中在某时间段，形成一波以某任务为中心的需求窗口；但部分学校明显错峰（写出名字），需要分别设计触达节奏。」用「多数 / 例外」，例外写校名；逐校日期放附录。

**3.3 差异化篇幅**：六个地区都要检查，但不必同样篇幅。

| 地区重要程度 | 正文深度 |
|---|---|
| 2–3 个核心地区 | 完整七层，展开主要用户情境与商业判断 |
| 其他有明确机会的地区 | 中等篇幅，突出差异和关键机会 |
| 数据不足或暂不重点投入的地区 | 简明说明（含覆盖情况），不强行编完整故事 |

核心地区由当月研究决定，**不永久固定为英国、美国**。「其他」地区保留各国差异。某地区有两个显著不同的群体，可以写两条策略路径，但不列十几个情境。

**不合格**：只复述校历；痛点是从日历直接推出的套话（「复习时间有限」）；没有三项结论。

### 第四章 · 地区优先级与机会判断（10%）

地区优先级是第三章的**结论**，不是由预设权重和覆盖率直接决定。

**4.1 六维判断**（定性排序，没有可靠商业数据时不用任意权重造精确分数）：

| 维度 | 要回答 |
|---|---|
| 时间机会 | 本月是否有明确且正在形成的需求窗口 |
| 需求规模与质量 | 目标用户规模及需求证据是否充分 |
| 购买条件 | 需求是否已接近咨询或购买决策 |
| 产品适配 | 我们是否有能有效解决问题的服务 |
| 商业价值 | 预计收益、获客成本、服务成本是否合理 |
| 执行可行性 | 师资、销售、营销能否及时承接 |

覆盖率默认矩阵（05 §7）只作初始提示。

**4.2 投入优先级与机会发展阶段分开**：投入优先级写「主攻 / 培育 / 观察」；同时写该地区机会处在哪个发展阶段（提前规划、集中准备、高紧迫、考后衔接）。「低即时成交机会」不等于「低地区重要性」：业务重要的地区在提前规划期，当前应经营潜在用户、积累线索，在更合适的窗口强化转化。

**4.3 输出两样**：
1. 地区决策表：地区｜本月主要机会｜关键窗口｜推荐优先级（主攻 / 培育 / 观察）｜机会阶段｜经营动作；
2. **本月核心机会主题，建议 2–4 个**（如「Final 考前冲刺」「假期备考」「考后衔接与续费」）。数量是建议范围：证据不足时可以少于 2 个，写明原因；不为凑数拆分或合并主题。每个主题写：跨哪些地区、哪类用户、窗口、为什么值得做。**地区是资源管理维度，机会主题是营销和产品组织维度**；第五、六章按机会主题组织。

### 第五章 · SKU 与产品价值策略（14%）

前四章回答「为什么这里有机会」，本章回答「我们到底卖什么，以及用户为什么会买」。

**5.1 先选 SKU，再提炼卖点**：目标用户的核心任务 → 深层痛点、决策标准与理想结果 → 服务能力与需求匹配 → 确定主推 SKU 或组合 → 从匹配理由中提炼价值主张。始终是**需求驱动产品**，不是先定 SKU 再编理由。

**5.2 卖点逐一回应用户关切**：

| 用户关切 | 产品需要的实际能力 | 可提炼的卖点 |
|---|---|---|
| （来自第三章 04、05 层） | （来自产品能力卡） | （对外表达方向） |

营销主张必须同时满足：**用户确实在意 + 产品确实能提供**。缺任一条都只是概念包装。产品能力未确认时，卖点写「需确认产品能力：……」，不写承诺（如不能因为学生在意速度就写「两小时配到老师」）。

**5.3 产品策略表**：策略机会（机会主题）｜对应地区与用户｜主推 SKU｜选择理由｜核心卖点｜必要交付条件。

**5.4 七个 SKU 都要表态**（灵活学Lite、安心学Max、学考无忧Pass、补考护航Pass、选课指导、论文稳Pass、先修班课）：主推 / 辅推 / 条件性承接 / 本月不推，不推的写一句原因。最终输出是可被营销、销售直接使用的**产品价值主张**，不只是「建议主推哪些产品」。

### 第六章 · 营销主张与促销策略（12%）

原则：**促销不是从月份出发设计，而是从用户购买决策中的阻力出发设计。**

**6.1 先分营销与促销**：营销回答「为什么你现在需要关注这项服务，为什么我们的方案值得选」；促销回答「在已认可服务价值的前提下，什么合理的商业机制能推动购买」。按这个顺序制定：明确目标用户与需求 → 提炼核心价值主张 → 分析当前购买决策阻力 → 选择促销机制 → 验证毛利、交付及规则限制 → 确定推广与转化方案。

**6.2 不同阻力匹配不同机制**（思考工具，不是套用规则库）：

| 主要阻力 | 优先考虑的干预 | 促销是否必要 |
|---|---|---|
| 不确定老师是否合适 | 诊断、试听、师资信息、匹配说明 | 不一定需要降价 |
| 时间紧，怕赶不上 | 明确服务启动流程、可用排课能力 | 折扣可能不是主要因素 |
| 不清楚需要多少课时 | 分阶段购买、课时组合、规划建议 | 可考虑降低初始决策门槛 |
| 价格敏感且已验证 | 满足利润约束的优惠、组合权益 | 可以考虑价格机制 |
| 老学员缺少续费动力 | 下阶段学情规划、课程衔接、合理续费权益 | 先分析续费原因 |
| 替代方案很强 | 差异化服务、教学效果证据 | 不能单纯靠价格竞争 |

候选机制从 02 §4 的促销目标与打法库（`docs/打法库/`）里选，过六个匹配条件（目标、用户、时间、产品、组合、业务边界）；时间适用性照 06 阶段 06（如考试只剩几天不推早鸟类）。

**6.3 每个促销方案论证六件事**：

| 维度 | 要求 |
|---|---|
| 促销目标 | 提高首次转化、客单价、续费，还是提前锁定需求 |
| 适用人群 | 哪些地区、新老用户、需求阶段 |
| 核心机制 | 降价、权益、组合、抵扣、赠课或非价格方案 |
| 选择依据 | 为什么这个机制能解决已识别的障碍，为什么不用其他候选 |
| 商业约束 | 毛利、退款、师资成本、与现行活动冲突 |
| 验证指标 | 如何判断带来了增量，而不是原有购买的价格让渡 |

同样是考前辅导，Final 冲刺、期中、毕业季的机制可以不同，依据要写出来。现行活动按「当月即时可用 / 跨月预告 / 满足条件后适用」区分时间口径，不把跨月权益当本月激励。不编具体金额（价格归价格模块）。

**「本月不额外促销，集中提升服务价值表达和转化效率」是合法结论**；不要求每个地区都有促销。

### 第七章 · 月度执行方针（9%）

把前六章转化为本月可执行的计划，只保留必要的执行框架，不再解释学生为什么需要辅导。两个维度：时间（何时准备、上线、转化、切换）× 部门。

| 工作方向 | 营销投放 | 销售转化 | 用户运营 | 师资交付 |
|---|---|---|---|---|
| 核心需求识别 | 需求型内容与受众测试 | 验证咨询需求和障碍 | 盘点老学员下阶段任务 | 提供常见学习问题与课程支持信息 |
| SKU 推广 | 明确卖点与传播素材 | 匹配产品方案和话术 | 老用户触达与课程衔接 | 确认可交付的课程能力 |
| 活动转化 | 活动推广与渠道投放 | 促销规则解释及成交 | 存量用户权益与续费 | 排课和老师匹配保障 |
| 效果复盘 | 线索质量及投放成本 | 成交与购买阻力 | 续费与用户反馈 | 交付体验与投诉风险 |

最后形成可执行事项：事项｜建议负责部门｜时间点｜依赖条件｜验收标准。具体负责人、预算没有确认的写「待指派」，不编。

### 第八章 · 关键假设与验证事项（3%）

只列会实质影响商业决策的 **3–5 项**，不罗列低价值 unknown：关键待验证问题｜为什么重要（影响哪个决策）｜验证方式（查什么数据、问谁）。其余未知放附录。

### 附录 · 研究依据（不计入正文）

院校时间表（逐校节点、核验状态、时间线疑点）；关键判断的证据链；结构化研判（情境、Claim、Evidence）；输入清单与规则版本；自检与独立审核记录；被否方案。

## 5. 深挖机制（比章节结构更重要）

章节结构对了，AI 仍可能只在各章填浅显信息。以下机制约束研究和综合两层。

### 5.1 六层分析

对每个核心用户场景至少回答：

| 层 | 必须回答 | 价值 |
|---|---|---|
| 1 事实层 | 用户真实处在什么时间、任务和情境下 | 定位问题 |
| 2 约束层 | 什么现实条件让任务变难 | 发现压力来源 |
| 3 动机层 | 用户真正想达成什么结果、避免什么风险 | 发现深层需求 |
| 4 决策层 | 用户用什么标准评价和选择服务 | 发现购买关键因素 |
| 5 价值层 | 现有产品如何比替代方式更好地满足需求 | 形成产品价值 |
| 6 策略层 | 应在何时、通过什么商业方式满足需求 | 形成实际行动 |

示例（考前约 20 天）：
- 浅层产出：任务＝期末复习；痛点＝时间有限；需求＝高效复习辅导；强度＝高。任何顾问凭经验都能写出来，价值有限。
- 深层产出：L1 客观任务：距 Final 约 20 天，需要完成期末复习 → L2 现实约束：时间有限、考试内容广、课程难度不同、能投入辅导的时间也有限 → L3 深层矛盾：需要的不只是更多学习时间，而是在剩余时间里找到最值得投入的复习内容与方式 → L4 购买决策标准：老师能否及时匹配、是否熟悉课程、能否快速诊断问题、是否针对考点 → L5 商业价值：产品应提供可及时启动、重点明确、适合有限时间的针对性支持，而不只是卖若干课时。

L1 是事实，L2–L5 是研究推导，要标注可信程度（5.7）。**缺少真实反馈时，不停在「可能需要辅导」，继续提出合理、可检验的机制假设，再区分哪些已被证实。** 这才是严谨分析，而不是谨慎到没有洞察。

### 5.2 需求三问

每个核心情境回答：用户表面上要什么（如找老师复习课程）？真正想解决什么（剩余时间有限，不知道怎样提高复习效率）？最终想得到什么（在有限时间内更有把握地完成重点复习和考试准备）？第三问决定卖点是「专业导师」「大牌师资」，还是「快速诊断」「针对性复习」「高效利用剩余时间」。**用户买的不是 SKU 名称，而是希望通过服务获得的进展**（Jobs to Be Done）。

### 5.3 不同学业节点的需求差异（研究框架）

| 用户阶段 | 核心任务 | 潜在深层矛盾 | 服务价值重点 |
|---|---|---|---|
| 开学初 | 建立学习基础 | 尚不清楚课程难度与自身准备程度 | 学习诊断、课程适应、提前规划 |
| 学期中 | 跟上进度、完成作业与阶段考试 | 多门课程持续占用精力 | 跟课支持、薄弱点补强、进度管理 |
| Final 前约 20 天 | 集中应对考试 | 时间与考试任务之间出现明显约束 | 快速匹配、重点定位、针对性复习 |
| 补考阶段 | 准备再次参加考试 | 原有学习方式可能未解决关键问题 | 原因诊断、针对性强化、重新规划 |
| 出分后 | 评价学习结果及下一步 | 尚未明确后续课程与支持需求 | 学情复盘、下一阶段规划 |

只是框架，按当月证据筛选成立的场景，不每月机械输出一遍。

### 5.4 需求洞察与购买障碍分开，中间加「决策标准」

「担心考前没有合适老师」包含两种信息：服务需求（希望快速匹配到熟悉课程的老师）→ 决定产品应具备什么能力；购买障碍（不确定我们是否有能力及时提供）→ 决定销售与营销如何建立信任。两者不能混为一个 barrier。分析顺序：

用户任务与现实约束 → 深层需求与理想结果 → **用户评价服务的决策标准** → 购买障碍、信任问题与行动时机 → 产品匹配、价值表达、商业干预

障碍编码体系（02）照用，但研究的是购买行为，不是机械套编码。

### 5.5 机会判断的四个维度

不再把 `need_strength` 当核心商业优先级。分开判断：

| 维度 | 研究什么 |
|---|---|
| 需求紧迫性 | 距关键任务还有多久，延误的后果 |
| 需求真实性 | 用户是否真的在寻求帮助，有哪些反馈或行为证据 |
| 购买成熟度 | 是否有意愿、预算、信任及明确购买计划 |
| 服务可行性 | 我们能否及时匹配老师、交付有效课程支持 |

四者可能完全不同。离考试只剩三天、需求极紧迫，但我们来不及诊断、排课和有效交付：不能因紧迫性高就判为最值得销售的机会，甚至应减少承诺、不主推常规课程方案。机会价值是四者的定性综合，不是公式。

### 5.6 竞争性解释

凡是会影响主推 SKU、促销方式或重大资源投入的核心判断，**至少比较一个有意义的替代解释**，并说明用什么证据排除或保留。例：考前咨询量上升，可能是考试压力上升、临考才意识到准备不足、早有需求但因价格或信任迟迟未买、某内容或渠道改变了咨询行为、考试时间集中使分散咨询聚集——它们对应完全不同的营销策略。比较过程留在研究层，正文只保留结论、关键依据和必要的不确定性说明。

### 5.7 证据来源与可信程度

四类证据来源：学校官方与外部信息（学业节点、院校差异、任务要求）；内部历史经营数据（地区规模、咨询转化、购买与续费变化，尤其**历史同阶段数据**：去年同一考试窗口，咨询何时开始增长、哪些地区先增长、购买集中在哪些需求、什么导致咨询未成交）；用户声音与一线反馈（真实痛点、决策阻力、购买语言）；产品及交付数据（SKU 适配、师资能力、服务表现与成本）。历史规律要控制比较口径：渠道、产品、校历、样本结构变了，不直接照搬。

正文关键判断标三档可信程度（只标关键判断，不逐句标）：

| 档 | 含义 | 典型依据 |
|---|---|---|
| 已验证 | 有直接事实或数据 | 官网核实的日期；背景卡事实记录；经营数据 |
| 有依据的判断 | 多条间接依据一致指向 | 原表日期；业务观察；同阶段历史规律 |
| 待验证假设 | 机制推演，合理且可检验 | 第 5.1 节 L2–L5 中没有证据的部分 |

底层 Claim 的 status / 证据强度规则（03 第 2 节、02 §2.3）照旧约束研究层；报告的三档是面向读者的表达，二者在附录里能对上。

## 6. 写作单位与写法

### 6.1 由 Claim 驱动改为 Insight 驱动

正文最小叙述单元是**洞察（Insight）**：Insight = 事实模式 + 解释机制 + 经营含义。

| 组成 | 内容 |
|---|---|
| 核心结论 | 一句话说明发现了什么重要现象或商业意义 |
| 事实支撑 | 哪些院校节点、业务观察或数据支持 |
| 解释机制 | 为什么会形成这种需求或决策行为 |
| 适用范围 | 适用于哪些地区、学校、用户群体 |
| 经营含义 | 这个洞察会改变什么策略选择 |
| 可信程度 | 已验证 / 有依据的判断 / 待验证假设 |

只有事实没有解释，不是完整洞察；只有解释没有事实，是假设；有事实有解释却不影响任何决策，不进正文。

### 6.2 写法规则

1. 结论先行；地区与重要段落用「结论 → 论证 → 行动含义」。
2. 写段落和必要表格，不写卡片；表格单元格可以短，正文不受「单条 40 字」限制。
3. 具体：有日期写日期，有学校写学校；地区归纳用「多数 / 例外」并写出例外校名；旬按日期算。
4. 敢下判断：证据不足时给出当前最有解释力的判断并标可信程度，边界集中写在节末或第八章 / 附录，**不在每句话里重复「可能」「尚待验证」**。
5. 同类信息只完整论证一次（3.3、3.4）。
6. 禁用空话（赋能、抓手、闭环、全方位、打造、助力、持续发力等）。
7. 不编：Evidence、学校、日期、经营数据、收入目标、价格金额、产品能力、负责人。缺了就写缺什么、影响哪条判断。

| 轮 | 做什么 | 主要输出（证据目录） |
|---|---|---|
| 1 完整研究 | SCOUT 阶段 01–05：事实、情境、Claim、初步机会、未知事项 | `facts.json`、`digest.md`、研判稿 `draft.json` |
| 2 洞察综合 | 跨学校、情境、地区归纳需求规律；挖关键矛盾（第 5 节）；比较竞争性解释；形成月度主线与机会主题 | `synthesis.md` |
| 3 商业策略设计 | 机会选择、SKU 匹配、价值主张、营销与促销机制、交付约束、行动路径 | `design.md` |

**负责生成大量 Claim 的那一步，不同时承担研究、洞察、商业设计和最终写作**；每轮单独完成、单独产出文件。第 5 轮审核方拿到：报告、附录、本规格、输入清单；不给生成过程。一次审核 → 一次返修 → 返修后定向复核；仍未解决的关键问题交常浩裁决，不无限循环。

## 8. 输入

### 8.1 必需

- **时间线底稿**：工作台 `strategy_facts`（只读）。
- **业务背景卡**：随底稿一起返回。整张未填时，第三章 04–06 层只能以「待验证假设」为主，第一章和第八章要说明这一点。

### 8.2 产品与活动（补充）

第五、六章要求「用户确实在意 + 产品确实能提供」，缺产品输入就写不实。

- **当月活动与价格**：试写期（批 C）允许 skill 只读：`GET /api/promos`、`GET /api/plans/<月份>/大学辅导`、`GET /api/v3/price/skus`（本机正式服务，只读，不写）。当月没有录入时，写明「本月活动未录入，以最近一个月（YYYY-MM）为基线」，不当成本月已生效。正式版本（批 D）改成工作台智能体工具，补进授权与留痕。
- **打法库**：仓库 `docs/打法库/P*.md`，作为促销候选机制池。
- **产品能力卡**：常浩提供，7 个 SKU 每个 3–5 行：交付什么、匹配到老师多快、能否加急、课时形式与最小购买单位、明确不提供什么。位置：`docs/策略输入/产品能力卡.md`（常浩确认后入库，改动走版本）。没有能力卡时，卖点一律写「需确认产品能力：……」，第五章在第八章列为头号验证事项。

### 8.3 历史同阶段数据（有则用）

去年同月的咨询、成交、续费变化。目前没有接入来源，试写期不要求；有了按 5.7 控制比较口径。

### 8.4 报告等级：输入决定报告能写到哪一级（v2.1 新增）

输入不全时也能写出一份「看起来完整」的经营方案，读者分不出哪份能直接执行。报告头必须写「报告等级」，按输入判定，**只能低报、不能高报**：

| 等级 | 输入条件 | 写法要求 |
|---|---|---|
| 研究假设版 | 业务背景卡「用户观察」「存量用户情况」都没填；或没有产品能力卡；或能力卡有 4 个及以上 SKU 一项都没填 | 第三章 04–06 层以〔待验证假设〕为主；第五章卖点写「需确认产品能力：……」；第六章**不出正式促销方案**：方案标题标「候选待确认」，或写本月不额外促销；第一章说明等级和缺哪些输入 |
| 条件性策略版 | 不属于研究假设版，但还没达到可执行策略版 | 主推和促销都写前提条件（每个促销方案在六项之外加「前提条件」）；第八章写清补齐哪项输入后可以升级 |
| 可执行策略版 | 「用户观察」「存量用户情况」都填了；每个主推 SKU 的能力卡五项都填了；活动基线就是目标月 | 按本规格正常写 |

- 判定依据是输入摘要（`digest.md` 的业务背景卡栏、`products.md` 的能力卡与活动基线），不是写作者的自我感觉；skill 的机械检查按这些输入核对，报告等级高于输入能支撑的等级就拦。
- 低报可以（例如输入齐全但用户证据互相冲突），第一章写明理由。
- 等级只说明输入能支撑多强的经营结论，不替代第 9 节的内容验收：研究假设版同样要深入解释、敢下判断并标可信程度。

## 9. 内容验收

现有八项自检（08 §3）继续负责事实和结构正确性；本节是**商业内容验收**，由第 5 轮审核预评、常浩终评。

### 9.1 六项评分（每项 0–5，总分 30）

| 维度 | 5 分标准 |
|---|---|
| 月度整体判断 | 准确概括周期、地区差异、主要机会与经营方向 |
| 地区需求洞察 | 不止描述节点，能解释用户任务、深层矛盾及购买机制 |
| 研究论证质量 | 关键结论有证据，能比较不同解释，准确说明不确定性 |
| 策略推导连贯性 | 从需求到机会、SKU、卖点和促销的逻辑完整 |
| 商业可执行性 | 方案符合资源、毛利、师资及实际业务能力 |
| 报告表达质量 | 结构清晰、重点突出、没有无意义的碎片化与重复 |

**门槛（初始，试写校准）**：总分 ≥ 24，且每项 ≥ 3。
**一票否决**（不以总分抵消）：关键事实错误；无依据的重大商业结论；无法兑现的服务承诺；违反毛利或交付约束的促销方案。

### 9.2 五个强制验收问题（全部成立才算有策略指导价值）

1. 只读第一章，能否准确理解本月的主要经营形势和主攻方向？（不成立：总览与主线失败）
2. 读六地区分析，能否说清各地区需求差异背后的原因，而不只是复述校历？
3. 对照主推 SKU，能否指出它具体回应了前文哪一个已识别的需求或痛点？
4. 对照营销及促销方案，能否解释为什么采用这种机制而非其他方式？（3、4 不成立：后半部分是独立编写的营销建议，不是推导出的策略）
5. 读完整份报告，营销、销售、用户运营和师资团队是否知道本月应优先做什么？（不成立：没有形成经营行动方针）

### 9.3 与 A–D 评级的关系

08 §2 的 A–D 评级保留，试写时两套同时打，校准对应关系后再定是否合并（批 D）。

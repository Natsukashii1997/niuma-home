# 08 · 质量标准 `quality-v1`

月度策略的两套评价互不混淆：客观质量评价（第 1 节）用来定位问题；负责人验收评价（第 2 节）回答「和常浩独立制定的相比质量如何」。另有每月的自检记录（第 3 节）和反馈分类（第 4 节）。

## 1. 客观质量评价

由自检和独立复审使用。每个维度 0–3 级：0 未达标、1 部分达标、2 基本达标、3 充分达标。用于定位问题，不汇总成总分。

| 维度 | 0 未达标 | 1 部分达标 | 2 基本达标 | 3 充分达标 |
|---|---|---|---|---|
| 事实准确性 | 有错误或过期的关键事实 | 关键事实正确，但有次要事实无来源 | 事实都有来源，个别推测未标注 | 事实都有来源，推测、冲突全部标注 |
| 需求识别 | 漏掉本月主要用户任务 | 覆盖主要任务，情境划分过粗或过细 | 主要任务和情境齐全 | 齐全，且识别出跨月衔接的需求 |
| 推理严谨性 | 推导链断裂，或把需求当成购买 | 有推导，但存在跳步 | 推导完整，限定条件写明 | 推导完整，反面解释也处理了 |
| 机会判断 | 优先级和证据明显不符 | 方向对，排序依据不足 | 排序有据 | 排序有据，并说明了放弃的方向 |
| 促销专业性 | 打法不适时、不适人或不适产品 | 适用，但缺少解释 | 适用且有解释 | 适用、有解释，与基线的差异也讲清 |
| 发布质量 | 结构混乱，部门难以理解 | 能读懂，但冗长或术语不统一 | 清晰、专业 | 清晰、专业，各部门能直接看出该做什么 |

**一票否决**：关键事实错误、核心推导失效、明显不适用的促销，三者出现任何一项，不论其他维度多高，都必须返修。

## 2. 负责人验收评价（A–D）

常浩只回答一个问题：「这版策略和我独立制定的相比，整体质量如何？」

| 等级 | 含义 |
|---|---|
| A · 超出预期 | 达到专业标准之上，提供了新的可信洞察或更优方案 |
| B · 达到预期 | 认可，可以直接采用，或只需少量编辑 |
| C · 部分达到 | 主要方向正确，但需要明显的专业修订 |
| D · 未达到 | 核心研判或策略选择不可靠，需要重新分析 |

- 评级之外，可选填原因：哪项判断特别准确；哪项与业务认知有偏差；哪个地区或场景漏了重要信息；哪个促销不合理；哪条分析给了新角度；哪些问题属于方法论缺陷，哪些只是本月信息不足。
- **B 级已经是很有价值的结果**，代表它能基本承担常浩原先的策略制定工作。A 级是持续深化的目标，不要求每次都追求大量新观点。
- 验收门槛：技术试跑至少 C；正式内容至少 B。

## 3. 每月自检记录

每次生成都写一份，存进 review 记录。

| 检查项 | 结果 |
|---|---|
| 事实与来源核验 | 通过 / 待确认 / 失败 |
| 地区与人群覆盖 | 通过 / 待确认 / 失败 |
| 任务与需求推导 | 通过 / 待确认 / 失败 |
| 购买障碍论证 | 通过 / 待确认 / 失败 |
| 机会排序合理性 | 通过 / 待确认 / 失败 |
| 促销匹配及适用性（批 2 起） | 通过 / 待确认 / 失败 |
| 章节一致性与反例检查 | 通过 / 待确认 / 失败 |
| 跨部门发布完整性 | 通过 / 待确认 / 失败 |

**结论规则**：关键事实错误、核心论证失效、促销明显不适用，必须返修；只有低风险未知项、并且已清晰标注时，才能带着待确认事项进入人工审批。

每个判为「待确认」或「失败」的条目，记录：位置（对象 ID）、问题类别、修复动作、复审结果。不能整份只写「全部通过」。正常情况下，页面只展示结论摘要，需要追溯时再展开证据。

## 4. 反馈分类与方法论修订

| 类别 | 例子 | 处理 |
|---|---|---|
| 内容级 | 「这段表述不够精炼」「这个地区漏了某校的节点」 | 只改本月策略，不影响规则 |
| 规则级 | 「这类用户不该归为没有购买意愿，因为根本没有相关证据」「需求温度一个维度表达不了这种情况」 | 进入方法论修订流程 |

**方法论修订流程**：

```
反馈 → 问题分类 → 规则修订候选 → 基准案例复验（新旧结果对比）→ 常浩批准 → 升规则版本
```

- 修订候选用认知深化提案的八个字段：当前定义、发现的问题、具体案例、修订建议、理论依据、影响范围、对照验证、审批结论。
- 不强制每月产生提案。没有实质改进点时，记录「本月未发现需要修订的通用规则」，这是正常结果。稳定运行也是成熟 Skill 的能力，不把每月修改自身当作进化指标。
- 任何规则升级，都要在基准案例上比较新旧结果，不能只看新规则表述是否更专业。

## 5. 基准案例库（批 3 建立）

| 案例类型 | 价值 | 入库条件 |
|---|---|---|
| 常浩正式认可的月度策略 | 高质量输出标准 | 评级 A 或 B |
| 发生过明显误判的策略 | 反面案例与防错规则 | 误判原因已写清 |
| 存在争议的用户情境 | 测试方法论的边界 | 争议点已写清 |

历史材料（如 2025 年策略文档、2026 年 10 月示例稿）也要先经常浩质量确认才能入库。历史回放生成的结果必须标「历史回放」，只用于基准评测，不能冒充前瞻发布。

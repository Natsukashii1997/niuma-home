## 目标

日报、周报各自读取独立来源，合并后在「日/周报」页和首页展示。未配置周报来源时，行为与现在完全一致。

## 一、配置：`weekly_doc_url`

1. 新增配置键 `weekly_doc_url`（可选）。校验规则与日报读取时对链接的要求一致：HTTPS、飞书域名、路径为 `/docx/<token>` 或 `/wiki/<token>`，不含账号、端口或空白。
2. **可空与清空**：`PUT /api/settings/weekly_doc_url` 传 `{ "value": "" }` 表示清空，直接删除该行，返回 `{ key, value: "" }`。其他三个键仍不允许空值，规则不变。
3. `report_doc_url` 的键名、已保存的值和校验规则都不变，不做任何迁移。
4. 设置页新增一张卡片「周报文档链接（可选）」，提示文案：「不填时，从日报文档中识别周报。」沿用现有「预览保存 → 确认保存 → 回读核对」流程，并增加：
   - **预览**：调用 `POST /api/reports/source-preview`（只读）试读该链接，显示识别到的周报篇数、最新一篇的标题、未识别的标题数。试读失败时显示原因，并且**不允许确认保存**。
   - 规范化后与日报链接相同时，预览提示「与日报文档相同，将按单文档方式读取」，此时允许保存。
   - **清空**：卡片里加「清空」按钮，同样经过「预览（提示将改为从日报文档识别周报）→ 确认 → 回读（该键不存在）」。

## 二、「第N周」标题解析

在 `server/report-parser.mjs` 中新增识别规则，已有的日期标题规则保持不变。

1. 匹配格式（允许前导图标、全角或半角括号、`-` `–` `—` `~` `至` 作为分隔、可多余空白）：
   `第{N}周 {Y}.{W}（{Y1}.{M1}.{D1} - [{Y2}.]{M2}.{D2}）`
2. 字段：
   - `kind` = 周报
   - `startDate` = Y1-M1-D1；`endDate` = 推算出的止日
   - **`date` = 起日 `startDate`**：沿用 T05 已有的「日期范围按首个日期排序」规则，保持兼容
   - `week` = N，`weekYear` = Y
   - `title` 保留标题原文，不做任何改写
3. 止日年份：标题写了 Y2 就用 Y2。没写时，M2 ≥ M1 取 Y1，M2 < M1 取 Y1 + 1（跨年，如 `2025.12.29 - 01.02`）。跨月的情况（如 `2026.09.28 - 10.02`）同年处理。
4. 以下情况判为**无效**，该标题不生成报告，记入该来源的 `unrecognized`（保留原标题与行号），不得静默丢弃：
   - 起日或止日不是有效日期（如 02.30）
   - 止日早于起日
   - 跨度超过 7 天（止日 − 起日 > 6）
5. 以下情况判为**不一致但仍收录**，在该篇的 `warnings` 数组里写中文说明，页面上显示为提示：
   - 「第N周」与「YYYY.W」中的周次不同
   - Y 与起日所在的 ISO 周年不同，或 W 与起日的 ISO 周次不同。例如 2026 年第 41 周按 ISO 计为 2026-10-05 起，与样例一致。
   - 原因：标题由人工撰写，以日期为准，不因周次笔误隐藏真实周报。
6. 报告层级、正文范围、HTML 表格转文字、代码块内的标题不切篇等规则，均沿用现有解析器。
7. 只读飞书文档，不修改源文档。

## 三、双来源合并

1. **读取模式**
   - **单文档模式**：未配置 `weekly_doc_url`，或它与 `report_doc_url` 规范化后相同（主机名小写、去掉末尾 `/` 和查询参数；比较规则见 API.md）。此时只读日报文档一次，日报和周报都从这份文档识别，行为与现在一致，另外能识别「第N周」标题。
   - **双来源模式**：两条链接不同。日报来源只收录日报，周报来源只收录周报；不属于该来源角色的篇目不收录，只在 `sources[].ignored` 中计数。
2. **ID**
   - 日报来源和单文档模式下的所有篇目，沿用现有 ID 算法，不加前缀，保证已有的深链接不失效。
   - 周报来源的篇目，ID = `w-` + `sha256("周报|" + date + "|" + title)` 的前 20 位 + `-` + 同键出现序号。
   - ID 只取决于来源角色、类型、日期、标题原文和同键出现顺序，与链接无关（换成同内容的另一份文档时 ID 不变）。正文修改、新增其他篇目都不改变已有 ID。
   - 现有 ID 都是十六进制开头，不会以 `w-` 开头，所以两个来源的 ID 不会冲突。合并时仍要检查是否有重复 ID；发现重复就返回 500，提示「日报周报编号冲突」，不能静默去重。
3. **排序**：按 `date` 倒序；同一天先日报后周报；再按各自在源文档中的先后顺序。
4. **详情**：`GET /api/reports/:id` 根据 ID 前缀判断属于哪个来源。如果该来源读取失败，返回该来源的错误（不返回 404），不去另一个来源里找，避免串篇。
5. **首页「最新日报」**：只取 `kind === "日报"` 的最新一篇。双来源模式下只看日报来源，周报来源失败不影响首页。

## 四、缓存、刷新与失败

1. 按来源分别缓存，以规范化链接为键；单文档模式只有一份缓存。
2. **有效期 10 分钟**，过期后下一次请求重读。这是对 T05「只在强制刷新时重读」的修改。理由：机器人每天写入日报，不过期的话首页会一直显示旧日报。并发请求合并为一次读取的机制保持不变。
3. 某个来源的链接改了或被清空，只作废这个来源的缓存，另一个来源不受影响。
4. `refresh=1` 时重读全部已配置的来源（同一链接只读一次），多个来源并行读取。
5. **读取失败**：作废该来源的缓存，下次请求重试，不返回旧内容（沿用现有规则）。
6. **单源失败不能当成空列表**：
   - 新的调用方式 `GET /api/reports?withSources=1` 返回 `{ reports, sources }`。部分来源失败时状态码仍为 200，`reports` 只含成功来源的篇目，失败来源在 `sources[]` 里带 `ok: false` 和错误原因。
   - 全部来源都失败时，返回日报来源的错误状态码与 `{ error, sources }`。
   - 旧调用方式（不带 `withSources`）保持数组形状，但任何一个来源失败都整体返回错误。这样不会把部分结果当成完整结果，旧调用方也不会误判。
7. 有正文但识别不到属于该来源角色的标题时，该来源判为失败，错误信息：「未识别到日报（或周报）标题」，并列出前 5 个未识别的标题。

## 五、页面

1. `ReportsPage.jsx` 与首页改用 `?withSources=1`。
2. 日/周报页顶部显示来源状态，例如：「日报文档：126 篇 · 周报文档：21 篇」。某个来源失败时，显示该来源的错误和「重试」按钮（即强制刷新），另一个来源的列表照常显示。
3. 来源有未识别标题时，显示「N 个标题未识别」，可展开查看原标题。
4. 周报列表项显示标题原文；有 `warnings` 时显示橙色小标签，悬停可看具体说明。
5. 不新增编辑、发送功能。

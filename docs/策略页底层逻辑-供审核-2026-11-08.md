## 1. 一句话结论与全景

策略页是一条从「学校日历」推到「促销打法」的推导链，分三层：

| 层 | 页签 | 职责 | 怎么产出 |
|---|---|---|---|
| L1 事实层 | 用户时间 | 把人工维护的时间线大表变成可信的事件清单 | 代码解析，再叠加官网核验和人工裁定 |
| L2 判断层 | 用户策略（上半部分：用户情况） | 从节点推到任务、痛点、决策障碍和机会点 | **AI 撰写**，人逐格修改 |
| L3 决策层 | 用户策略（下半部分：促销策略）+ 促销打法 | 按决策障碍从打法库匹配促销组合 | 规则匹配，不调用模型，同一输入永远得到同一输出 |

```
飞书时间线 ──解析/核验──▶ 事件清单 ──AI 撰写──▶ 月度用户情况 ──规则匹配──▶ 促销策略
   (L1 来源)              (L1)                 (L2)                    (L3，查打法库)
```

**关键依赖**：L3 只读取 L2 的「地区分档」和「决策障碍」来计分选卡。L2 这两格写得对不对，直接决定促销结果。

## 2. L1 事实层：用户时间

### 2.1 来源

- 飞书电子表格《2026海外大学时间线》：4 张地区明细表（美东美西加拿大、英国爱尔兰、澳大利亚新西兰、香港澳门新加坡马来西亚）和 12 张月历。
- 同步时整表只读，任何一张读取失败都不覆盖上次成功的快照。
- 支持登记后续年份的表（如 2027），各年份的数据按「年份前缀」隔离。

### 2.2 每一格怎么解析

| 情况 | 结果 |
|---|---|
| 能读出完整「月 · 日」或日期区间 | 确定日期；区间跨年时按文档年份补全 |
| 含「推测、预估、预计、去年、左右、上旬、中旬、下旬、月初、月底」等词，或带「研究生、本科生、国际生、专业、校区」等适用对象限定 | 标 **guess（推测）** |
| 多段日期、缺结束日、日期非法、同一学期开学日前后不一、Final 早于同行的下半年开学日 | 标 **conflict（冲突）** |
| 只知道月份 | 不补成具体某天，只在对应月份的视图里显示为「待确认」 |

原则：工作台不替学校猜日期；推测和冲突单独标出（页面上统一显示为「AI推测」）。

## 3. L2 判断层：月度用户情况

规范见 `docs/用户策略规范.md`（2026-10-19 与常浩逐轮确认后定稿）。

### 3.1 定义与边界

- **用户策略**：针对某个月，判断目标用户所处的时间节点和状态，拆出他们要完成的任务、卡在哪里、为什么还没购买，从中收敛出机会点，最后给出促销建议和背后的逻辑。
- **对象**：海外大学生，以本科为主；硕士只在与本科明显不同的关键节点上附注。只覆盖大学辅导，不含申诉服务，也不含国际课程。
- **产出止于促销建议**：不定具体价格（定价归价格模块），不写触达话术，不做上月复盘。

### 3.2 推导链

```
时间节点 → 待办任务 → 核心痛点 → 决策障碍 → 心理机制 → 打法
（情境）    （任务）    学业阻力      购买阻力      为什么有效
```

**痛点和障碍必须分开**：痛点是学生完成学业的阻力（例：写不好 Essay）；决策障碍是学生选择我们的阻力（例：觉得还来得及）。打法只针对障碍，不针对痛点。

规范要求：每一段只使用上一段的结论，不回头补充信息。

### 3.3 时间窗

目标月整月，加下个月前 14 天。后者标「提前预热」，不和当月节点混写。

### 3.4 地区与权重

7 个地区，按权重排序：英国 ≥ 美国 > 香港 > 澳洲 > 加拿大 > 新加坡 > 其他。「其他」合并了新西兰、澳门、爱尔兰、马来西亚。

### 3.5 地区分档

分档 = 固定权重 × 本月节点密度：

- **主战场**：权重高且本月有节点；或权重中等但节点密集（例：澳洲 11 月同时有 Final、出分、补考）。
- **次要**：有节点，但权重或密度一般。
- **平稳**：本月基本没有节点。

规范原文说分档「只用于标注和排序，不决定篇幅」。实际上分档还是 L3 的计分系数（见 4.1）。

### 3.6 文档结构

| 段 | 内容 | 谁产出 |
|---|---|---|
| 0 核心结论 | 一句话月度判断（≤100 字） | AI 写 |

| 1.2 共性与差异 | 跨地区共性、差异、外部变量（双 11、圣诞假等） | AI 写 |

| 3 机会收敛 | 跨地区机会点合并排序：`[P0/P1/P2, 机会, 地区, 业务线, 新签/续费, 窗口, 依据]` | AI 写 |

### 3.7 地区 6 格

| 格 | 写什么 | 不写什么 |
|---|---|---|
| 用户节点 | 学期第几周、关键事件及日期、代表学校；当地消费节点、中国节点 | 与本月无关的远期节点 |

### 3.10 写作规范

1. 结论先行：每段第一句就是判断。
2. 每条都有依据；没有依据的标「AI 判断」。
3. 具体化：有日期写日期，有学校写学校，有数字写数字；不写「大部分、较多、一定程度」。
4. 一条一个意思：单条不超过 40 字，以动词或判断开头。
5. 术语统一：障碍名、打法名、心理机制名一律使用词表写法；正文不写编号。
6. 禁用空话：赋能、抓手、闭环、全方位、深度、打造、助力、持续发力。

### 3.11 校验 `checkInsight`

- **拦截（不能保存）**：缺地区；分档不是三档之一；温度不是 `[冷|温|热, 冷|温|热]`；每格不在 0/1–6 条范围内；条目不是 `[正文, 来源]`；来源不在 6 种标注里；障碍编号不在词表里；机会条目不是 7 列。
- **只提示**：单条超字数（正文 40、核心判断 100、机会名 20）；用了禁用词；正文里出现编号。

## 4. L3 决策层：促销策略（规则匹配）

代码为 `server/user-strategy.mjs` 的 `matchPromo`。2026-10-20 与常浩确认，用它取代原来的模型生成。

### 4.1 匹配规则（按执行顺序）

1. **障碍计分**：每个地区的每个决策障碍按该地区的分档计分（主战场 3、次要 2、平稳 1），跨地区累加。
2. **排序**：分数高的在前；同分时先比涉及的主战场地区数，再按词表顺序 A1 → C1。
3. **分两栏**：新签栏只用阶段为「新签」或「通用」的卡，续费栏只用「续费」或「通用」的卡。续费栏不处理「不信任效果」「没被触达」，理由是老学员已经买过、已在触达范围内。
4. **逐个障碍选卡**：按排序依次处理每个障碍，在打法优先表里取第一张同时满足三个条件的卡：阶段合适、本栏还没选过、不与本栏已选卡冲突。本栏第一张卡为主打法，其余为辅助。每栏最多 4 张。某个障碍如果已经是某张已选卡的主障碍，就不再单独选卡。
5. **冲突**：
   - 卡片正文「不宜组合」一段里点名了另一张卡的名称，两张卡就不进同一栏，判断是双向的。目前共解析出 28 对。
   - 同一栏只用一种直接降价（限时折扣、直降 / 立减、支付立减、早鸟价、阶梯降价）。
6. **4.3 不选什么**（最多 3 条）：因冲突跳过的候选、障碍已被覆盖而没用上的首选卡、因满 4 张没轮到的首选卡。不足 2 条时，补已选障碍的第二候选。
7. **4.4 底线**（固定三条）：
   - 毛利：同一订单只叠加一种让利，加赠按成本价计入毛利。
   - 价格锚点：老学员价 ≤ 早鸟价 ≤ 限时价 / 立减价 < 正价，违反不上线。
   - 合规：不承诺成绩与通过率；退款、价保等条款写明期限。

### 4.2 打法优先表

**新签栏**

| 障碍 | 候选（按优先级） |

| 觉得还来得及 | 早鸟价 → 涨价预告 → 封班 / 截止报名 → 定金预售 |
| 不信任效果 | 免费试听 / 公开课 → 7 天无理由退 → 学习保障条款 → 低价引流课 |
| 有替代品 | 赠 1v1 课时 / 答疑 → 正课 + 服务打包 |
| 嫌贵 | 满额加赠门槛 → 分期免息 → 赠题库 / 会员 |

| 4.2 作用路径 | 主心理机制的标准释义 |

### 4.4 打法库（「促销打法」页签）

- 共 47 张卡，分 11 类：价格让利、时间窗口、量价组合、产品与陈列、权益加赠、体验与诊断、风险保障、预售与支付、老客与会员、定向触达、互动激励。来源是飞书《路觅教育线上课程促销打法手册》，做过合并、改名和增补。
- 每张卡第二行有隐藏的元信息：编号、类别、阶段（新签 / 续费 / 通用）、主障碍、辅障碍、心理机制（第一个为主机制）。示例：`<!-- P0201 | 类别 2 | 阶段 通用 | 障碍 A2 ; B1 | 机制 M05 M03 M10 -->`
- 卡片正文有七节：心理机制、用户决策路径、适用信号、不适用与反作用、方案设计、组合、文案示例。
- 心理机制共 23 种（锚定效应、损失厌恶、现时偏差、零价格效应、后悔规避、权威效应、信息缺口等），每种有一句标准释义。

### 4.5 示例：2026-11

障碍计分：

| 障碍 | 分数 | 来自 |
|---|---|---|
| 不信任效果 | 8 | 美国、澳洲（主战场），新加坡（次要） |
| 没时间 | 8 | 美国、澳洲（主战场），新加坡（次要） |
| 觉得还来得及 | 7 | 英国（主战场），香港、加拿大（次要） |
| 有替代品 | 6 | 英国、美国（主战场） |
| 嫌贵 | 5 | 英国（主战场），加拿大（次要） |
| 没被触达 | 4 | 澳洲（主战场），其他（平稳） |
| 怕选错 | 2 | 香港（次要） |

输出：

- 本月目标：新签以免费试听 / 公开课主攻期末冲刺、结课作业与 1 月备考；续费以自选课包承接下学期续报。
- 新签栏：主打法为免费试听 / 公开课（不信任效果）；辅助为自选课包（没时间）、早鸟价（觉得还来得及）、赠 1v1 课时 / 答疑（有替代品）。「嫌贵」「没被触达」「怕选错」因满 4 张没有轮到。
- 续费栏：主打法为自选课包（没时间）；辅助为早鸟价（觉得还来得及）、积分体系（有替代品）、多科联报（怕选错）。
- 4.3：满额加赠门槛、老学员续报价，理由都是「嫌贵」已由自选课包覆盖。

### 4.6 匹配逻辑文档自己列出的已知问题（2026-10-20）

1. 优先表是人工排的，顺序是否合理、是否漏了更合适的卡，需要逐个障碍复核。
2. 没有用到时间信号：卡片「适用信号」写了时间条件（如早鸟价要求距开课 4–8 周），但没拿来对照当月节点，所以 Final 只剩 1 周的地区也可能配到早鸟价。
3. 续费栏借用了新签的障碍：用户情况只写了潜在新用户的障碍，老学员特有的障碍（如「上学期效果一般」）没有数据来源。
4. 续费栏主打法常和新签栏某张辅助卡相同，是否需要错开未定。
5. 「不宜组合」靠名称匹配：别称会漏，顺带提到的名称会误判。
6. 直接降价的 5 张卡名单写死在代码里，新增卡片要人工同步。
7. 作用路径用的是机制通用释义，和具体打法、当月场景对不上。
8. 每栏最多 4 张、按分数截断，导致两栏覆盖不一致。
9. 适用窗口取机会点窗口的并集，太宽，没有对应到打法本身该上线的时段。
10. 4.4 底线是固定文字，不随选中的打法变化。

## 5. 三层之间怎么衔接

- **L1 → L2 的同步**：打开用户策略时，代码用最新时间线快照（含官网核验和人工裁定）重算时间全景、节点数和推测清单，并和这个月正文写作时的依据做指纹对比。依据变了，页面提示「时间线依据已更新」，但**不自动改写正文**，只提醒人工核对。
- **L2 的修改**：核心判断、1.2、1.3、地区 6 格、机会收敛都可以逐格修改，一行一条。改过的行来源标「你写的」。所有写入都要先预览、后确认。
- **L2 → L3**：点「生成促销策略」，即时出预览，确认后保存，状态分草稿 / 定稿。4.1–4.4 不能手改，只能重新生成；已定稿的要确认覆盖。不保留历史版本。

## 6. 对新 skill 的设想（Claude 的推断，常浩尚未确认）

| 层 | skill 是否接管 | 理由 |
|---|---|---|
| L1 时间线 | 不接管，只读结果 | 已经是代码解析 + 官网证据 + 人工裁定 |
| **L2 用户情况** | **接管生成与更新** | 目前唯一靠 AI 写正文的一层，也是对结果影响最大的一层 |
| L3 促销匹配 | 不接管 | 确定性规则；skill 只需要知道 L3 怎么使用分档和障碍 |

skill 的输入是某个月的时间线事实，输出是一份能通过 `checkInsight`、写作规范和证据要求的整月用户情况。它需要覆盖两种场景：从零生成某月；时间线依据变化后更新已有月份。

## 7. 梳理中发现的缺口

| # | 缺口 | 证据 | 影响 |
|---|---|---|---|
| 1 | 用户情况的依据已经过期 | 11 月正文基于 10-20 的时间线；11-07 同步并叠加 130 格官网核验后，接口返回依据状态 `changed`，正文没有更新 | 12 个月都可能用了被核验推翻的日期 |
| 2 | 「事件 → 需求」对照表没有成表 | 规范只举了一个例子；代码和文档里没有完整的表，但需求温度说明 97%（124/128）标的是「规则推导」 | 「规则推导」这个来源实际上没有可追溯的规则 |
| 3 | 分档没有可判定的标准 | 「权重 × 节点密度」只有定性描述，没有阈值 | 分档直接决定 L3 的 3 / 2 / 1 计分，改一档就可能换主打法 |
| 4 | 决策障碍证据最弱 | 131 条全部是「AI 判断」；Voice 原声没有接入 | 对促销结果影响最大的一格没有任何外部证据 |
| 5 | 两处地区顺序不一致 | 规范写「英国 ≥ 美国」；时间线页面的国家顺序是美国在前 | 只影响显示，不影响计分 |

## 8. 请重点审核的问题

1. **推导链是否成立**：「时间节点 → 待办任务 → 核心痛点 → 决策障碍 → 心理机制 → 打法」，每一步之间的跳跃是否有依据？尤其是从「痛点」到「决策障碍」：障碍是购买阻力，它能从时间线和痛点推出来吗？还需要什么输入？
2. **决策障碍词表**：9 项是否互斥、是否完整？续费场景是否需要一套独立的障碍（见 4.6 第 3 条）？
3. **分档标准**：怎样把「权重 × 节点密度」写成可判定的规则？3 / 2 / 1 的计分是否合理？
4. **「事件 → 需求」对照表**：应该包含哪些事件类型、提前多少天、对应什么需求温度变化？请给出一版草案。
5. **证据分级**：6 种来源标注是否足够？「AI 判断」是否应该细分（如常识推断 / 类比往年 / 无依据）？哪些格子必须有非 AI 来源才能进入 L3 计分？
6. **L3 匹配规则**：除 4.6 列出的 10 条已知问题外，还有哪些逻辑漏洞？时间信号应该怎么接入匹配？
7. **skill 的边界与流程**：按第 6 节的设想，skill 应该包含哪些步骤、检查点和人工确认点？依据变化后的「更新」应该怎么做，才能既不推翻人工修改、又能修正过期日期？
8. **结构本身**：第 3.6 节的 0–4 段加附录，是否最适合「月度业务决策 → 拆给营销、产品、运营执行」这个用途？有没有多余或缺失的部分？

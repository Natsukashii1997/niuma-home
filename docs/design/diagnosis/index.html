1 · 底层逻辑关联

工作台的数据靠两样东西串起来：「月份」和「SKU」。现在的问题是这条链在 UI 上是断开的：每页各看各的，看不出一个月的方案、价格、物料、brief 是不是齐了。改版的核心就是让这条链在界面上连起来。

逻辑层面的问题，会直接决定 UI 怎么改

问题后果改法（UI 层面）
L1月份语义错位：首页和方案页都盯着「本月」，但你的工作是「本月准备下月，月底前交付」10 月显示「0/3 未录入、促销 0 ▼7」，像出了问题，其实正常；真正该盯的 11 月却没人提醒全局引入「交付月 = 下个月」：首页主卡、月度台账、价格、brief 默认都定位到交付月，同时可以切换月份
L2价格信息有两份：促销表的「正价」是文字（如「¥4300（赠课版）」），新签和续费里还写着赠课阶梯；价格方案又是一张结构化矩阵两边迟早对不上，查价格要翻两处价格以「价格方案」为准；促销表的价格格子显示方案名，可以点开看矩阵；赠课阶梯在价格页做成「赠送课时」方案
L3SKU 没有主表：SKU 是文本加别名，物料用 JSON 存 SKU 名；同名 SKU 在两条业务线是两个东西价格档位、物料关联、筛选都容易错位UI 上 SKU 一律显示成「业务线 · SKU」，用统一的 SKU 选择器（Codex 实现 SKU 主表）
L4物料类型没配置，设置里还是示例；共识已经定了类型（价格图、试听、选课、活动、三宫格、九宫格）物料筛选和跨月对比没法用物料页直接用共识的类型；设置里预填，你可以改
L5日报里的「T 线」（T 线-双11 战役、T 线-产品）其实就是项目和战役，但日报是一大段 Markdown 文字项目进度要靠你人工从日报里提取日报渲染成事项表，T 线做成筛选标签，并能跳到对应的项目或战役（自动匹配由 Codex 做）
L6文案助手不认识 brief，助手和 brief 是两个孤岛写 brief 时要来回复制brief 右侧常驻助手，带着当前段落和知识库

4 · 新功能页面

价格 重设计已定：A 矩阵 + 顶部单价曲线

给谁用常浩，负责定价和测算主角同一个 SKU 的「课时档 × 价格方案」，以及相对基准方案的差价最常做的 3 件事① 跨方案看同一档的差价 ② 新增或调整一套方案（直接改格子）③ 看单价阶梯合不合理信息层级SKU 页签 → 顶部是单价曲线的小图（一套方案一条线，悬停对齐）→ 主体是矩阵（总价是大字，课时单价、折扣、差价是小字）→ 底线和校验提示口径课时单价 = 总价 ÷（课时 + 赠送），这是主值，与共识 Q22 一致；同时显示付费单价 = 总价 ÷ 课时，对应你表里的写法

用户时间线 重设计已定：按国家用明细表，按月用议程

主角准确的「学校 · 事件 · 起止日期」信息层级顶部是全局搜索和筛选（国家、事件类型、学期）。「按国家」是清洗后的明细表，结构和飞书原表一致，冲突和推测的格子单独标出，点开看源单元格。「按月」是议程，按周分组，每条写全，跨周的事件在每周开头注明仍在进行。「异常清单」是一个页签，显示待确认的条数不放什么不用点阵代替日期，不截断文字，不用颜色区分国家（国家写文字）

知识库整理 重设计已定：可编辑树 + 暂存区 + 规则批量

主角比飞书更快地把文档放到对的位置交互多选（⇧ 和 ⌘）、拖动、⌘X/⌘V、F2 重命名、⌘⇧N 新建目录、⌘Z 撤销；原位置留一个灰色虚影；底部是暂存条，写明「N 项变更 · 预览并同步」；右侧是规则批量面板

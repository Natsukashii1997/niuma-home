## 1. 总评

整体已经到了「规整的工具界面」水平。位图风底座、48px 卡头、32/28px 控件、StatStrip 在大多数页面都做到了。动效也克制：全站没有 CSS transition，每页最多两种按帧组件。

最主要的 3 个问题：

1. **接上真实数据后，出现了信息错误和文字截断**。下次重置时间「未公布」，同时又显示「已到重置时间」；时间轴里的短事件被切成「Fina」「Wit」「期中假 1」；项目数字条指错了节点。示例数据里这些都看不出来，换成真实数据第一眼就错。
2. **颜色语义只写进了规范，没落到组件**。信号橙仍同时表示「待处理」「风险」「上升」「降价」四种意思；规范第 5 节还保留着旧规则，和第 1 节矛盾。另外，页面底的点阵直接压在页头文字上，被读成标点。
3. **同类模式各写一套**。阶段条有 4 种画法，筛选有 3 种控件，空、加载、报错状态有 5 种表达。「列表 + 详情」两栏等高以后，详情栏或列表栏留下 800–900px 空白。

#### P0-1 Codex 重置：「未公布」和「已到重置时间」同时出现
- **位置**：全站顶部 Codex 横条；`#/home` Codex 大卡右半区。
- **看到**：截图 `r01-home-codex-card.png`。
  - 横条写着「下次重置时间未公布　已到时间」。
  - 大卡写着「下次重置时间未公布 / 已到重置时间」，后一句是信号橙 15px。
  - 原因：接口返回 `next: null`，`useCountdown(c?.next || 0)`（`CodexStrip.jsx:40、:63`）把空值当成「时间已过」。
- **为什么**：两句话互相矛盾。横条每个页面都有，而且用了报警色，读起来像出了事。
- **怎么改**：
  - `next` 为空时不算倒计时。横条的 `.codex-cd` 写「等官方公布」，用 muted 色；大卡右侧只留时间说明（label）和一行「每天 10:00 检查」。
  - 只有 `next` 有值并且已经过了，才显示「已到重置时间」。颜色用 `--ok`，因为额度重置对使用者是好消息，不用信号橙。
- **改动量**：小。只影响横条和首页大卡。

#### P0-2 用户时间线（按月）：短事件名被截断，「推测」斜纹没有图例
- **位置**：`#/user/timeline` 的甘特条。
- **看到**：截图 `r02-timeline-truncated-labels.png`、`r02b-timeline-truncated-closeup.png`。
  - 事件名被切：多伦多大学「Wit」、ANU「Fina」、罗切斯特「选课」只剩半个字。
  - 日期被切：美国各校「期中假 1」「期中假 11-2…」「期中假 11-26 → 1…」。
  - 香港、澳门的「期中」和 BU 的「选课」是斜纹条，但图例只有「冲突待确认」，没有「推测」。
- **为什么**：这页的主角是准确的「学校 · 事件 · 起止日期」。诊断第 4 节明确定了「不截断文字」。真实数据里很多事件只有 1–3 天，条宽只有 30–90px，放不下「类型 + 起止日期」。另外斜纹用 `rgba(255,255,255,.7)` 叠出来（`styles-v3.css:588`），违反规范第 1 节「不用透明度」。
- **怎么改**：
  1. 条宽放不下文字时，色条照画，文字放到条的右侧（墨色 12px）。右侧被下一条占住时，换到下一行（lane）。单日事件已经有 `is-single` 的外置写法，把它推广到所有放不下的条。判断方法：条宽 = `(to − from + 1) × 日宽`，和估算的文字宽比较。
  2. 跨月事件现在写「Final ← 10-24 → 11-07」，「←」和「→」连在一起不好读。改成「Final 10-24 起 → 11-07」。
  3. 「推测」改用 `--dither-1` 网点（只铺在条的右半段无字区），或者把左边色条改成 3px 虚线，不再用 rgba；图例里补上「推测」。
- **改动量**：中。只影响时间线按月视图。

#### P1-1 信号橙兼了四种语义（跨页面）
- **位置与证据**：用脚本读计算色，值为 `rgb(255,79,31)` 的文字有这些：
  - 首页「待我处理」的「审核」「价格」类型框，以及日期「10-17」（`.todo-kind.is-urgent`，`styles-v3.css:130`）；
  - 日/周报列表里的「1 待处理」（`ReportsPage.jsx:90` 用了 `.signal`）；
  - 价格矩阵里所有负差价，例如「−310 · 单价 −62」（`.price-diff.is-down`，`:274`），以及 200h 格子「毛利 24% · 低于底线」的左线；
  - Voice 的「上升 +27」（`.trend.is-up`，`:666`），但同页词云图例里「上升」是墨色；
  - 物料墙的「待交付」格是橙色虚线框（`.wall-empty.is-pending`，`:329`），和「示例」标记的画法一模一样；
  - Codex 大卡头部的阶段标签写死成 `tone="orange"`，而弹窗里同一阶段按 `STAGE_TONE` 用绿或蓝（`r01b-codex-modal-stage-tone.png`）。
- **为什么**：规范 v2.2 第 1 节规定，信号橙只用于「当前项、新信号、主操作悬停」；待处理用琥珀，风险用红。现在看到橙色，分不清是「要我处理」「出了问题」，还是「只是比基准便宜」。差价是比较值，本身不是风险。
- **怎么改**：

  | 现在 | 改为 |
  |---|---|
  | 待我处理 ·「审核」/ 等你审核 | `tag-amber` |
  | 待我处理 ·「价格」（低于毛利底线） | `tag-red` |
  | 待办日期（明天到期） | `.warn-text`；当天或已过期才用 `.risk-text` |
  | 日报「N 待处理」 | `.warn-text` |
  | 价格负差价 | `--text-2`；只有低于底线的格子用红，左线也改成 `--risk` |
  | Voice「上升」 | 墨色 600，和词云图例一致；「急升」保留信号橙（属于新信号） |
  | 物料墙「待交付」 | 琥珀实线框 + 琥珀字；虚线只留给「示例」和空状态 |
  | Codex 阶段标签 | 卡片和弹窗都用 `STAGE_TONE`（确认绿、预告蓝、修正琥珀、撤回红） |

  这些地方继续用信号橙：侧栏选中竖条、交付月标记、今日格、当前阶段顶条、急升、Voice 排名 01、打字效果里的数字高亮、今日日程的当前项。
- **改动量**：中，约 8 处 CSS/JSX。涉及首页、价格、Voice、物料、日/周报。

## 3. 跨页面的系统性建议

1. **把语义色落到组件，并修规范第 5 节**。
   - 组件只认语义类：`.is-ok`、`.is-risk`、`.is-info`、`.is-pending`。`--signal` 只给 `.is-current` 和 `.is-new` 用。
   - 第 5 节现在还写着旧规则，和第 1 节矛盾：
     - Tag：`green` 表示墨底、`blue` 表示墨框、`orange` 表示待处理；
     - `.state`：已完成墨底、进行中墨框；
     - `.warn`：橙色左线。
   - 代码里这些已经是语义浅底，第 5 节应按代码重写，否则之后的修改会继续照旧规则做。
2. **虚线只表示两件事**：橙色虚线 = 示例，灰色虚线 = 空状态或空位。禁用、待交付都不用虚线。
3. **新增 4 个公共组件**：
   - `PhaseSteps`：阶段条（P1-10）；
   - `FilterChips`：标签组筛选，附和 Segmented 的选用规则（P1-11）；
   - `StateBlock`：报错、加载、空状态三种，替换 `Loadable` 里的纯文字（P1-12）；
   - `ListDetail`：左列表右详情，统一处理等高、吸顶和列表滚动（P1-9）。
4. **版式规则补 3 条**（写进规范第 6 节）：
   - 吸顶位置统一用 `--sticky-top: 80px`（P1-14）；
   - 规则②补一句：「列表 + 详情」时两栏框等高，较短一栏的内容吸顶；
   - 页面说明的位置和字体（P2-2）。
5. **字号刻度**写进规范第 2 节（P2-1）。
6. **名称对照表**写进规范第 7 节：

   | 概念 | 统一叫法 |
   |---|---|
   | 侧栏模块 / 页面主题 | Voice / 留学之声 |
   | 需求 | 主线需求 |
   | 业务线 | 用全称：大学辅导、国际课程、申诉服务 |
   | 品牌模块 | 品牌 |
   | 物料 | 物料沉淀（页签）/ 物料墙（视图）/ 物料交付（首页环节） |
   | 价格 | 价格记录（页签）/ 价格方案（单个方案） |

7. **每接一个真实接口，都用真实数据截图验收一次**。P0-1、P0-2、P1-4、P1-6 都是换成真实数据后才出现的。验收时不只看「示例」标记消失，还要专门检查：最长的文本、空值、单日和跨月事件、0 和特别大的数。

## 4. 对已定方案的异议

**异议 1：首页 Codex 大卡占了左上角最好的位置**
- **现状**：大卡占左上 8 栏、约 300px 高。同样的信息在每个页面顶部的横条里一直都有。营销负责人每天打开首页，第一眼该看的是「待我处理」和「交付月」。现在大卡大部分时间处在「确认 · 下次未公布」这种不需要任何操作的状态。
- **建议**：大卡保留，但做两种状态：
  - 「确认」「撤回」或下次时间未公布时，收成 72px 高的一行（引文 + 阶段 + 检查时间）；
  - 只有「预告」并且有倒计时的时候，才展开成大卡。
  - 另一种做法：和交付月卡互换位置。
- **代价**：改变了用户点名要求的布局，需要用户确认。改动小：`HomePage` 网格顺序 + `CodexCard` 加一个紧凑状态。

**异议 2：规则②「并排等高」在「短列表 + 长详情」时只能留空白**
- **现状**：项目推进左列只有 3 个项目，右边节点表很长。按规则只能把左列拉长，留下约 830px 空白。P1-9 给的改法（内容吸顶）不突破规则，但空白仍然在。
- **建议**：给规则②加一个例外：「侧边列表栏可以不拉伸，和右侧顶对齐，内容吸顶」。
- **代价**：版式测量脚本里「底边差为 0」的检查要排除这类侧栏；视觉上这一行的底边不再齐平。如果用户更在意底边齐平，就保持 P1-9 的改法。

## 5. 不建议改的地方

下面这些看过，认为已经合理，下一轮不要返工：

- **位图风底座**：冷灰点阵 + 2px 细线 + 直角 + 无阴影，全站统一，风格成立。只需按 P1-2 处理点阵压字。
- **7×7 像素图标**：侧栏、卡头、按钮里的尺寸和视觉中线基本一致。
- **卡头 48px、工具栏控件 32px**：实测全站卡头只有 48px 一种（Agent 聊天头和日报文档头除外，见 P2-11）。
- **StatStrip**：知识库健康检查（整格可点）、项目推进「5 格对 5 个阶段卡」、带教 4 格都好用，保留。
- **营销战役的月底倒计时条**：31 格、今天一格橙色、交付日一格空心，读得懂，信息密度合适。
- **价格矩阵的结构**：「课时 × 方案」，每格写总价 + 单价 / 折扣 + 差价，横向比较效率高。
- **设计 brief**：目录 / 正文 / 助手三栏，上一节 / 下一节导航，九宫格可以直接编辑。
- **设置页**：「名称 · 值 · 状态标签 · 编辑」的行式列表，是全站最规整的列表。
- **月度促销**：「粘贴 → 解析 → 处理 → 确认」四步，加左右两栏的流程结构。
- **业务页**：红黄绿 + 时间进度竖线的读法。
- **动效**：全站没有 CSS transition；每页最多两种按帧组件；溶解只在切换模块时出现。
- **自言自语抽屉**：操作悬停才显示，底部有键盘提示，不打扰。
- **弹窗**：墨色网点遮罩 + 2px 墨框。

## 1. 定义与边界

**月度用户策略**：以全球留学生的真实学业时间线为基础，识别特定月份的用户情境、待完成任务、学业困难和购买决策障碍，提炼值得关注的业务机会，形成有明确依据的用户策略与促销方案。

**定位**：专业研判型。目标是替代常浩每月从零梳理、思考、论证、撰写策略的工作量，不以营收增长作为 Skill 质量的直接判据。

**要回答的六个问题**：

1. 这个月，学生正在经历什么？
2. 这些学生真正需要完成什么？
3. 哪些用户需求值得我们关注？
4. 我们应该提出什么策略？
5. 本月应该如何促销？
6. 这些判断为什么可信？（贯穿全程的质量要求）

**三条边界**：

- 策略面向真实业务，但不接管一线执行：可以提出市场、销售、用户运营、师资应关注的重点，不产出完整投放计划、销售话术、排班方案。
- 促销是策略的核心组成，不是唯一组成：前面的用户研究要为促销选择提供有力解释，而不是为某张优惠卡找理由。
- 策略质量独立于经营结果评价，但不脱离经营现实：历史业务结构、产品、价格、师资是背景约束，只是暂不把经营效果作为自动改写 Skill 的反馈信号。

**范围**：海外大学辅导，本科为主，硕士只在与本科明显不同的节点上单列研究生情境。不含申诉服务、国际课程。不定具体价格（定价归价格模块）。

## 2. 推导链

**学业需求链**（阶段 03）：

```
时间节点 → 待完成任务 → 学业困难 → 期望进展 → 潜在支持需求
```

**商业决策链**（阶段 04）：学生为什么考虑或不考虑购买辅导。需求存在，不代表购买自然发生；学业困难、外部支持需求与购买意愿必须独立判断。

**促销链**（阶段 06）：

```
用户机会 → 购买障碍 → 促销目标 → 候选打法 → 适用校验 → 方案组合 → 专业论证
```

痛点是完成学业任务的阻力，障碍是选择我们的阻力。打法针对障碍，不针对痛点。

运行流程是 SCOUT-8 八阶段，见 [06-SCOUT-8运行规范](策略规则/06-SCOUT-8运行规范.md)。

## 3. 整体结构

| 段 | 名称 | 内容 |
|---|---|---|
| 0 | 核心结论 | 当月全局判断、重点用户与主策略方向 |
| 1 | 全局研判 | 全球时间节点、需求时间窗、地区共性与差异、外部变量、各地区策略优先级 |
| 2 | 用户洞察 | 五大地区 + 其他，每个地区单元 8 个字段（见下） |
| 3 | 机会收敛 | P0 / P1 / P2 机会及对应用户、地区、业务方向 |
| 4 | 促销策略 | 4.1 本月促销总判断 · 4.2 主推方案 · 4.3 辅助与地区特殊方案 · 4.4 适用边界与不采用的方案 |
| 附 | 依据与待确认 | 关键依据、未知项及其获取途径、策略限制 |

每个主要策略下加一行「部门协同关注点」，不单独新增执行规划章节。

**地区单元 8 个字段**：① 用户情境 ② 关键节点 ③ 待办任务 ④ 核心痛点 ⑤ 需求状态（学业需求强度与购买准备度分开）⑥ 决策障碍（新签、续费分开）⑦ 机会点 ⑧ 研判依据（折叠显示）。每个字段的数据来源见 [03-Schema-v2](策略规则/03-Schema-v2.md) 第 6 节。

**正式稿与内部研判记录分开**：正式稿供发布给其他部门，内容专业、清晰、有结论、有依据；内部研判记录保存证据、假设、被否方案、自检问题，作为 Skill 提升质量的基础。

## 4. 地区体系

英国 ≥ 美国 > 香港 > 澳洲 > 加拿大 > 其他（新加坡、马来西亚、新西兰、澳门、爱尔兰及以后新增国家）。

- 底层分析细到国家、学校和用户情境；正式策略以五大地区 + 其他组织呈现。「其他」只是展示层的合并，各国时间线不合并。
- 业务地区权重、当月需求活跃度、当月策略优先级是三个不同概念，见 [05-需求生命周期](策略规则/05-需求生命周期.md) 第 6、7 节。

## 6. 写作规范

对标一线互联网公司的策略文档：精炼、专业、结构清晰、逻辑严谨。

1. **结论先行**：每段第一句就是判断。
2. **主张 + 依据**：每条都有依据，判断状态和证据强度如实标注。
3. **具体化**：有日期写日期，有学校写学校，有数字写数字；不写「大部分、较多、一定程度」。
4. **一条一个意思**：单条不超过 40 字，以动词或判断开头。
5. **克制表达**：证据不足时，写「可能带动……，尚需……验证」，不写「普遍缺乏……，因此急需……」。
6. **术语统一**：障碍、打法、心理机制一律使用规则文件里的名称；正文不写编号。
7. **禁用空话**：赋能、抓手、闭环、全方位、深度、打造、助力、持续发力等。
8. **未知照实写**：未知项写明缺什么、能否获取；不用「待确认」三个字逃避分析，也不编造来源。

字数、禁用词、正文编号只提示、不拦截；结构和不变量违反即拦截。

## 7. 飞书版

每月一篇《用户策略 · YYYY-MM》，放在飞书知识库「策略 / 用户策略」目录下，内容是正式稿，并补充：

1. 事实依据：每个关键节点的学校、日期、核验状态；推测和冲突单独列出。
2. 时间全景图：地区 × 节点。
3. 主要促销的论证：主张、依据、推理、条件、反驳。
4. 待确认清单：全部未知项及其获取途径。

内部研判记录不进飞书正式稿。

## 8. 内容来源与状态

- **生成**：月度用户策略 Skill 在 Claude / Codex 会话中运行，按 SCOUT-8 研判后，通过 `strategy_submit` 提交；常浩在工作台页面预览、确认后写入。工作台本身不调用模型（第一、二批）。
- **人工修改**：可以逐格修改，改过的内容标 `origin=manual`，之后的自动更新不改写它。
- **版本**：每次确认写入形成不可变的 revision，可以查看差异、回退；独立复审和常浩的 A–D 评价单独追加，不改变 revision。
- **更新**：时间线日期或业务事实变化后，只更新受影响的判断（refresh 模式，批 3）。
- **验收**：技术试跑至少 C，正式内容至少 B，见 [08-质量标准](策略规则/08-质量标准.md)。

# 个人工作台 · 总体定位与需求总览

更新：2026-10-15。总体目标已由用户明确表达；能力展开、完整事项清单与建设顺序仍待梳理。本轮只整理需求，不开发。

## 1. 用户明确的总体目标

> 我希望把我工作中所有的事项都接入到这个工作台中，最终实现的目标就是除了在飞书发消息，其他所有常见的工作都可以在工作台找到对应解决途径，都能帮我更好的完成。

据此，work-desk 的长期定位是：**常浩处理日常工作的统一入口，围绕具体工作事项提供资料、判断支持、操作路径和可用成果。**飞书发消息继续在飞书完成。

这次表达把此前营销、价格测算、时间线、策略、知识库等需求归入同一个目标；没有撤销任何已有决定，也没有自动确认尚未回答的功能取舍。

“所有常见工作”是需要逐步覆盖的完整目标。当前清单仍不完整，不能据此宣称整体完成比例，也不能将少数先做的功能变成总目标的缩减版。

## 2. 对产品的含义（助手建议，待整体校准）

- **按工作事项组织能力。** 用户从“我现在要完成什么”出发，能找到对应资料、方法、工具和下一步；页面布局与导航形式后续再定。
- **把相关步骤接起来。** 查资料、分析、测算、形成方案、准备执行、记录结果之间尽量复用上下文，减少重复查找、复制和解释。
- **用可用成果判断完成。** 查阅类任务拿到可靠资料，分析类任务形成有依据的判断，测算类任务得到可解释结果，执行类任务有明确的结果回读。仅有链接或静态页面不等于该工作已得到支持。
- **保留数据来源与生效位置。** 工作台内的草稿、个人整理、试算结果，与飞书／NAS 等原系统中的正式内容区分清楚。
- **允许人作关键判断。** 用户保留成本口径、价格底线、策略取舍和采纳决定；AI 可辅助分析、整理和拟稿，不能将候选建议自动当作业务决定。

对无法在工作台内直接完成的步骤，技术探索应说明能否通过受控调用或带上下文的原工具衔接解决；仍需跳出的范围和不足明确列出，不能用普通跳转链接默认为已满足用户的完整目标。可接受的例外由用户判断。

### 营销策略：设计参考

**用户已明确：**在营销策略中新增「设计参考」板块，以画布形式呈现；上传的素材以悬浮效果放在画布上，带白色描边。用户会把看到的好素材放进来，之后对接海报制作时，可以直接找到参考内容。

**使用目标：**把平时零散收集的视觉素材积累成可回看的参考，海报对接时能选出具体样本，帮助说明想要的效果。画布形式、悬浮效果和白色描边是已确认方向；背景色、描边宽度、阴影、布局与动画尚未确定，后续由 Claude 按项目分工细化视觉规范。

**建议的使用过程，待整体校准：**收集素材 → 放到画布 → 归组并标注参考点 → 海报对接时查找、挑选和引用。

- 画布支持素材自由拖拽摆放、缩放／平移浏览，重新进入后保留布局；支持放大查看原图。悬浮首先表达为有层次的素材卡片，是否需要动画不预设。
- 可按活动、产品、风格或用途归组，补充标题／标签并搜索，避免画布内容变多后再次难以查找。单画布还是多个主题画布待定，不强制按月分类。
- 每份素材可记“参考什么”，例如配色、版式、字体层级、主视觉、文案或信息组织，并保留来源链接／备注。海报对接时将选中的素材与参考点关联到具体活动或方案；是否导出参考集合、怎样分享后续再明确，本轮不对外发送。
- 收集对象以用户提供的素材为准；图片／截图可作为首批候选，网址、PDF、视频等类型与批量上传方式尚未确定，不自动抓取外部网站或下载其素材。

**与月度物料和存储的关系：**设计参考用于灵感收集和设计沟通；已有月度物料用于查阅公司活动素材，两者可以关联，不能默认混为同一集合或重复上传。用户此前明确不希望大量月度物料占用本地，故建议设计参考也优先评估 NAS 存放原文件、工作台保存索引／备注／布局的方式；这尚不是本板块已确认的存储决定，NAS 目录与上传权限仍需核查，本轮不上传或改动 NAS。从画布移除参考与删除原文件应分别定义，不默认联动删除。

**候选验收：**收集若干真实参考后，能在画布看到悬浮效果与白色描边，重新打开仍可找到素材和自己的整理；海报对接时能找到一组参考，并说清各自参考什么。界面好看之外，需要实际支持“找回并用于沟通”。素材不可访问、上传失败与保存失败应明确显示，不伪装为已收集。

**当前状态：**只记录需求，交互与存储方案未定；尚未形成正式派单、API、视觉稿或代码。继续遵守“暂不开发”。

### 首页通知：Codex 重置预警

**用户已明确：**仅在工作台首页增加「Codex 重置预警」通知，来源为 [AIHOT 的 Tibo 重置监控](https://aihot.news/codex-reset)。展示下一次明确的重置时间、Tibo 原话、北京时间及还剩多少天／小时；每天北京时间 10:00 更新，发现重置信号时更新工作台，并通过机械邪龙兽在飞书推送给本人。不扩展为 AI 新闻模块、独立侧栏或个人额度查询。

**时间与事实口径：**

- AIHOT 已换算的北京时间直接使用，不能二次加时差。若需根据原帖中的 PT 换算，按事件日期采用 `America/Los_Angeles` 到 `Asia/Shanghai`，处理夏令时；明确的固定 UTC 偏移按其原义，PST／PDT 表述与日期规则冲突时标记待核实，不静默选择。
- 区分“有明确重置预告”与“精确时间已公布”。原帖明确到时刻才显示精确的天／小时倒计时；仅给日期、时间窗口或截止时间时保留原精度，并标明是窗口还是截止。AIHOT 按惯例推算或额外放宽的时间属于估计，不能显示为确定时刻。
- 时间未公布时显示“已预告，时间待定”；没有新预告时显示“暂无已公布的下一次重置”。不以历史频率、确认帖发布时间或页面更新时间生成倒计时。
- Tibo 原话使用来源收录的英文原句，中文译文另列，附原帖链接和 AIHOT 链接；较长原帖只展示与重置有关的短原句。保留适用范围，未说明时明确写未说明。
- 额度重置与重置卡发放分开标注，不能把发卡等同额度恢复；原帖未明确形式时不擅自补成“全员重置”。确认帖时间不等于精确执行／到账时间，到账核实也不等于 Tibo 发了确认帖。

**据此建议的工作过程，待整体校准：**浏览文档清单 → 理解内容与关系 → 保存分类草稿 → 预览逐项变更及影响 → 用户确认选定批次 → 同步飞书并回读结果。

- 清单展示完整标题、当前位置、文档类型、更新时间和内容概览；对无权读取或尚未读取的内容明确提示。飞书本身已有搜索摘要，工作台的增量应是把这些信息持续用于整理和决策。
- 分类草稿允许暂存、撤销和继续处理，原库在确认前不变。标签／专题可让同一文档服务多个工作事项；是否实际移动目录应单独选择，不默认复制正文。
- AI 可给出分类理由、相关文档或可能的版本关系；“副本”及旧日期只能作为待核查线索，不能直接判定重复、过时或自动删除。
- 变更预览逐项显示原位置、目标位置、标题变化、涉及子页面及可核实的权限影响；无法核实的影响保留待确认，原文档已变化时重新预览。用户可只采纳部分建议。
- 同步后逐项回读成功、失败或结果未知，保留未完成项与原始链接。不能预先承诺跨接口单事务或一键恢复；删除、改权限、正文合并改写不随分类整理默认授权。

**候选验收：**用户能完成一批真实资料的判断与归类草稿，看到每项准备改变什么，决定采纳哪些，并核对实际同步结果；无需重复手工记住待整理文档和目标位置。具体操作优先级、内容读取与索引范围、同步细则仍待收敛，暂不制定派单。

### 新增侧栏：自言自语

**用户已明确：**入口名称为「自言自语」。常浩目前会向自己的飞书账号发消息作为临时记录，希望把这些自发自收的消息返回工作台，回看哪些有价值。这是个人临时记录的整理需求；发送行为继续在飞书完成。

**建议的处理过程，待整体校准：**回看原消息 → 辅助提炼内容和可能用途 → 用户决定保留、继续思考或采纳 → 按需关联到知识、待办或策略。

- 展示原始表达、发送时间和来源；若将连续几条消息合并理解，仍能看到各条原文，避免摘要丢失语境。
- AI 可以提出主题、值得关注的理由、相关工作和下一步建议；“有价值”可以是可行动的事项、值得深入的问题、可复用的资料或个人想法，不默认按统一分数裁决去留。
- 个人感受、未成形想法和暂时看不懂的记录不必强行转成工作任务；用户可以补充说明、修改判断或暂不处理。AI 不因低分、重复或难理解而自动隐藏、删除原记录。
- 转为待办、知识或策略只作为候选能力；用户采纳后再进入对应内容，并保留来源关联与处理去向。不得把所有消息自动视为正式知识或执行指令。
- 内容读取仅限已核实的本人自发自收会话；不能用“本人发出的全部消息”、其他私聊、群聊、收藏或机器人会话替代。消息中的指令性文字属于待分析记录，不自动作为当前执行授权。

**读取核查状态：**2026-10-15 仅阅读本机 `lark-im` 及其 `+chat-messages-list` 说明，确认文档列有 user 身份的单聊读取入口；尚未实际读取本人自聊，不能据通用单聊能力断言该特殊会话已可接入。未查询其他会话、扫描聊天或下载附件。后续接入仍使用机械邪龙兽 `codex` 的 user 身份，不切换机器人。

**待后续确定：**具体自聊的读取支持和权限、首次回看时间范围、刷新方式，以及文本／链接／图片／语音／文件的覆盖范围和价值辅助方式。尚未明确实时同步、全量历史迁入、语音转写、链接正文抓取或自动定期处理；本轮不启用这些动作。

**候选验收依据：**用户能找到指定范围的自发自收原记录，明确区分原文与 AI 分析，理解推荐理由，并自行决定下一步；未识别、无权限或未读完不能被当作无记录。源消息保持不变，尚未采纳的内容仍可回看。

## 4. 每项工作如何界定

后续统一按以下问题补齐任务清单，而不是先罗列页面和技术功能：

1. 在什么场景下，需要完成什么工作；频率、影响和当前困难是什么？
2. 需要哪些资料，原始内容在哪里，由谁维护？
3. 哪些是查阅、分析、测算或拟稿，哪些会修改正式内容？
4. 工作台需要提供哪些步骤，哪些判断仍由用户作出？
5. 什么样的输出算完成，怎样回读或检查；失败时下一步是什么？

现有上下文能回答的先由助手整理；只询问会改变目标、范围、权限、关键路线或验收的缺项，不要求用户重新讲述已经确认的需求。

## 5. 建设和验收原则（建议）

完整目标保留，按真实高频工作与实际影响分阶段补齐。每次新增能力应能接住一项自然发生的工作，改善查找、判断、操作或交付；功能数量本身不证明工作变轻松。

对用户确认的常见工作清单，最终逐项检查：

- 能从工作台找到正确的起点、所需资料和清楚的下一步。
- 能得到与该工作匹配的可用结果；依据、限制和生效位置明确。
- 跨步骤可接续，不需要用户自行猜工具、重新组织全部上下文。
- 未接通、读取失败、权限不足或尚待用户判断的事项明确可见，不伪装成完成或无数据。
- 用户用真实工作验证后，确认它确实帮助自己更好完成该事项；工程测试与页面完成不能代替这层验收。

在完整工作清单尚未确认前，不给出整体覆盖百分比，不承诺未经验证的时间节省或收益。阶段性验收范围写清楚，不混同为整个工作台已完成。
